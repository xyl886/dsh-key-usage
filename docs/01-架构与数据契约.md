客户端与服务端**只通过同源 HTTP 端点通信**；计费规则以用户 YAML 文件为唯一事实来源，
客户端经 `GET /pricing` 读、经 `POST /pricing/rules` 写（服务端原子写 `pricing-rules.yml`，改完刷新页面即生效）；
聚合价目经 `GET /pricing` 的 `aggregate` 块读、经 `POST /pricing/refresh` 让服务端刷新（写本机 `model-prices.json`）。

## 2. 客户端契约

### 2.1 产物形态（不能改）

- 入口：`src/client/index.tsx`（`tsdown.config.ts` 的 `entry`）。
- 产物：`client/client.js`，单文件 CJS，`platform: browser`，`target: es2022`。
- 外层头必须是单行：

  ```js
  window.__ModuleLoader__.load({ id: "dsh-key-usage", factory: (require) => {
  ```

  由 `scripts/normalize-client-banner.mjs` 在构建后强制校验；头不匹配会 `exit 1`。
- `react` / `react/jsx-runtime` 是 external，由宿主 `require` 注入；其余 import 全部打进 bundle。

### 2.2 CSS Modules 内联机制

`tsdown.config.ts` 里的 `dsh-css-modules-inline` 插件把每个 `*.module.css` 变成虚拟模块：

- 用 lightningcss 编译，`cssModules.pattern = '[hash]_[local]'`（类名会加哈希前缀）。
- 注入一个 `<style data-plugin="dsh-key-usage" data-plugin-css="dsh-key-usage/<文件basename>">`。
- 去重键是 **`插件id/文件basename`**：

  ```js
  if (document.querySelector('style[data-plugin-css="dsh-key-usage/section.module.css"]') === null) { …append… }
  ```

  ⇒ **不同目录下的同名 CSS 文件，后一个会静默不注入**。拆样式时 basename 必须唯一。
- 另有一份 `globalThis.__DSH_PLUGIN_CSS__` 注册表（`{tagId, css}[]`）供宿主侧复用。

## 3. 服务端契约

### 3.1 通用规则

- 全部 `GET`、只读；`Cache-Control: no-cache`；`Content-Type: application/json; charset=utf-8`。
- `requireLoopback(request, response)`：`socket.remoteAddress` 不是 `127.0.0.1` / `::1` / `::ffff:127.0.0.1` 时返回 `403 {"error":"loopback only"}`。
- 家目录解析：`process.env.DSH_HOME ?? ~/.dsh`（`routes.ts: dshHomePath()`）。
- 文件缺失 / JSON 损坏 → 返回**空态而不是错误**：

  | 情况 | 响应 |
  | --- | --- |
  | 台账缺失或损坏 | `/usage` → `{totals:null, days:[], availableFrom:null, availableTo:null}`；`/heatmap` → `{days:[]}` |
  | 快照缺失或损坏 | `/quota` → `{providers:[]}` |
  | cordis.yml 缺失 | `/channels` → `{channels:[]}` |

### 3.2 `GET /dsh-key-usage/channels`

```jsonc
{
  "channels": [{
    "provider": "opencode-go",          // cordis.yml providers 下的键（provider id）
    "displayName": "opencode-go",
    "apiKeyEnv": "OPENCODE_GO_API_KEY", // 环境变量名，无则 null（绝不读值）
    "baseURL": "https://…",
    "models": [{ "id": "glm-5.3-flash", "name": "GLM-5.3 Flash", "contextWindow": 1000000 }],
    "costMode": "sub",                  // sub | perToken | free | none | unknown
    "costLabel": "订阅制",               // 服务端给出的中文标签
    "status": "warn",                   // ok | warn | danger | off
    "quotaPercent": 76,                 // 订阅窗口最高占用，无则 null
    "quotaWindowKey": "month",
    "quotaWindowLabel": "本月",
    "balanceText": null,                // 余额展示文本（含币种，原样），无则 null
    "snapshotUpdatedAt": 1790762819897  // 快照写入时间，无则 null
  }]
}
```

顺序：`llm-deepseek` 条目（若有）被 `unshift` 到最前，其后是 `llm-pi-ai.config.providers` 的声明顺序。实测当前本机为 4 个：`deepseek-official` / `sensenova` / `local` / `opencode-go`。

**判定规则**（`collect.ts: classifyChannels`，客户端只负责展示）：

| 顺序 | 条件 | costMode | status |
| --- | --- | --- | --- |
| 1 | `apiKeyEnv` 为空 | `unknown` | `off`（未配置） |
| 2 | provider 为 `local` 或 baseURL 指向 127.0.0.1 / localhost / 0.0.0.0 | `none` | `ok` |
| 3 | 快照有 `plan.windows` | `sub` | 最高占用 ≥90 `danger`、≥60 `warn`，其余 `ok` |
| 4 | 快照有 `balance` | `perToken` | 余额 ≤0 `danger`、<10 `warn`，其余 `ok` |
| 5 | `FALLBACK_COST_MODES` 显式登记（当前只有 `sensenova → free`） | 该值 | `ok` |
| 6 | 以上都不命中 | `unknown` | `ok` |

提取规则（`collect.ts`）：

- `llm-pi-ai` 段：`^ {4}providers:$` 起，到下一个 0 列 `- id:` 止；provider 块为 6 空格键名，模型为 10 空格 `- id:`。
- `llm-deepseek` 独立条目：模型在其 `config.models` 下（6 空格 `- id:`），`provider` 固定为 `deepseek-official`，`displayName` 固定 `DeepSeek`。
- **不能换成通用 YAML 解析器**：文件里有 `!!js` 表达式，解析即执行。改规则必须配样本测试。
- YAML 标量的成对引号会被剥掉（`'GLM-5.3-Flash '` → `GLM-5.3-Flash `，尾随空格保留）。

### 3.3 `GET /dsh-key-usage/usage`

| 参数 | 说明 |
| --- | --- |
| `from` / `to` | `YYYY-MM-DD`，缺省取台账首/末日；闭区间 |
| `provider` | 逗号分隔的 **provider id** 列表；缺省不过滤 |

```jsonc
{
  "totals": { "date": "", "calls": 11189, "inputTokens": …, "outputTokens": …, "cacheReadTokens": …,
              "cacheWriteTokens": …, "reasoningTokens": …, "cost": 7.1 },
  "days": [{
    "date": "2026-09-30", "provider": "",           // 注意：日级行的 provider 固定为空串
    "calls": 370, "inputTokens": …, "outputTokens": …, "cacheReadTokens": …, "cost": 0,
    "models": [{ "provider": "opencode-go", "model": "GLM-5.3-Flash ", "date": "2026-09-30", "…": "同 LedgerModelEntry" }]
  }],
  "availableFrom": "2026-09-07", "availableTo": "2026-09-30"
}
```

- `days` 只包含**当天有数据**的日期（无记录的日期被跳过，不会补 0 行）。
- `days[].models` 按 `input+output+cacheRead` 降序。
- `totals.date` 固定为 `''`。
- `hours`：**仅当 `from === to`** 时返回 24 个小时槽 `{ calls, buckets: { inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens } }`，其余情况为 `null`。这份数据来自**会话事件**（不是台账），所以与同一天的 `days[0]` 不保证逐位相等 —— 界面在按小时视图下标注了来源，且不显示成本。

### 3.4 `GET /dsh-key-usage/heatmap`

范围 = `max(台账首日, 今天-364 天)` ~ 台账末日（**服务端不返回未来日期**，未来格由客户端补齐）。

```jsonc
{ "days": [{ "date": "2026-09-30", "totalTokens": 137900000,
             "models": [{ "provider": "opencode-go", "model": "GLM-5.3-Flash ", "totalTokens": 120000000 }] }] }
```

- 只包含 `totalTokens > 0` 的日期；`models` 按 `totalTokens` 降序，同 provider 同名模型已合并。
- 客户端拿不到「台账起始日」本身，只能用 `days[0].date` 近似 —— 这是当前热力图「台账尚未覆盖」判定的依据（见 02 文档 O6）。

### 3.5 `GET /dsh-key-usage/quota`

```jsonc
{ "providers": [{
    "provider": "opencode-go",
    "displayName": "opencode-go", "credential": "OPENCODE_GO_API_KEY",  // 变量名，不是密钥
    "source": "live",              // live = 刚查到的官方数据；snapshot = 回落本机快照
    "fetchedAt": 1760…,            // 实时查询时间（source=live 时有效）
    "updatedAt": 1759…,            // 快照时间 / 或等于 fetchedAt
    "error": null,                 // no-key / network / timeout / unauthorized / http-<code> / bad-json / no-snapshot
    "balance": { "currency": "CNY", "totalBalance": "1.50" },         // 官方返回的归一化字段
    "plan": { "windows": [{ "key": "5h|week|month|day", "percent": 19, "resetsAt": "2026-10-13T15:00:00.000Z" }] }
}]}
```

- 每个**已配置通道**一条；`balance` / `plan` 可为 `null`。
- 实时查询见 `live-quota.ts`：`opencode-go` → `GET https://opencode.ai/zen/go/v1/usage`（`rolling`/`weekly`/`monthly` → `5h`/`week`/`month`）；`deepseek-official` → `GET {baseURL}/user/balance`；另有 openrouter / moonshotai / zai 的官方余额接口。
- **币种来源**：接口自带 `currency` 优先 → 否则按 host 推断（`*.moonshot.cn` → CNY、`api.z.ai` → USD、`open.bigmodel.cn` → CNY）→ 都没有才用方案默认值。z.ai 的余额端点**没有官方文档**，币种只有「定价页注明 USD」这一点有依据。
- **时间字段**：`resetsAt` 同时接受 ISO 字符串与 epoch（毫秒/秒/数字字符串）并统一归一为 ISO，识别不出时原样返回，避免界面显示「重置于 1791903600000」。
- **响应上限**：`MAX_RESPONSE_BYTES = 65536` **按 UTF-8 字节**计算（不是 `string.length` 的 UTF-16 码元数）。
- **回落顺序**：实时（60 s 缓存）→ **插件自己的快照**（`$DSH_HOME/dsh-key-usage/quota-snapshots.json`，每次实时成功即写）→ 宿主的 `provider-snapshots.json`（可能很旧）→ 无。两份快照**取 `updatedAt` 更新的那一份**，`error` 与 `updatedAt` 一起透出，界面据此显示「失败原因 + 快照有多旧」。
- **`supported`**：该通道是否存在官方余额/窗口方案（`schemeIdOf(channel.provider) !== null`）。`false` 表示**根本没有接口可查**（免费额度、本地端点），界面只显示口径说明、不再提示「实时查询未成功」。
- **错误分档**：`no-key` / `network` / `timeout` / `unauthorized`（401 与 403 合并，OpenRouter 的 403 表示「需要 Management Key」）/ `http-<code>` / `bad-json` / `too-large` / `no-snapshot`；厂商契约 fixture 见 [`test/fixtures/providers/`](../test/fixtures/providers/)（36 个，逐条标注官方/社区/推断来源）。
- **写盘**：本插件只写 `$DSH_HOME/dsh-key-usage/` 目录下的三个文件 —— 这里的 `quota-snapshots.json`（原子写、best-effort、失败静默）、计费规则 `pricing-rules.yml`（见 §3.13，写失败要给原因）与刷新下来的聚合价目 `model-prices.json`（见 §3.15，校验不过不覆盖），不碰宿主的任何文件。
- 6 秒超时、64 KiB 上限、60 秒缓存（`?fresh=1` 强制重查）；任何失败回落快照并把原因放进 `error`。
- 宿主的 `provider-snapshots.json` 由「dsh-usage」能力写入，本插件只读；本机实测它最后写入停在 **2026-09-30**，这正是需要自带快照的原因（见 `quota-snapshots.ts` 顶部注释）。

### 3.6 `GET /dsh-key-usage/summary`

总览表用的「今日 / 近 30 天」按通道汇总，全部来自**台账**。

```jsonc
{
  "channels": [{ "provider": "opencode-go",
                 "today": { "provider": "opencode-go", "calls": 0, "tokens": 0, "cost": 0 },
                 "month": { "provider": "opencode-go", "calls": 10588, "tokens": 4090000000, "cost": 0 } }],
  "range": { "today": "2026-10-13", "monthFrom": "2026-09-14" }
}
```

- 「今日」按**服务器当天**计算；「近 30 天」= 今天往前 29 天到今天。
- 没有用量的通道返回全 0（不是缺项），前端据此显示 `—`。

### 3.7 `GET /dsh-key-usage/sessions?limit=200`

```jsonc
{
  "rows": [{
    "id": "session-43c91b48-…", "title": "开发 DSH Key 用量插件" ,
    "archived": false,      // 宿主侧是否已归档（只做标记，用量照常计入）
    "workspace": "D:\\EasyJob", "provider": "opencode-go", "providerLabel": "opencode-go",
    "firstTime": 1791…, "lastTime": 1791…, "calls": 128, "tokens": 42000000,
    "cacheHitRate": 96.2, "days": 3, "crossDays": 2,
    "prompt": "把会话用量这页加上详情抽屉…",   // 首条真实提问片段（≤200 字，搜索与兜底标题都用它）
    "models": [{
      "provider": "opencode-go", "model": "GLM-5.3-Flash", "tokens": …, "calls": …, "buckets": {…},
      "sharePercent": 82.4,   // 占该会话展示口径 tokens 的百分比（一位小数）
      "cost": 12.3, "costSource": "rule"   // 逐模型成本与来源（与整行同一套口径）
    }],
    "costMode": "sub",      // 该通道的计费模式
    "cost": null            // 台账可估价时为估算金额，否则 null
  }],
  "coverage": { "status": "complete", "totalSessions": 12, "countedSessions": 12, "skippedSessions": 0 },
  "priced": true
}
```

- `rows` 按 `lastTime` 倒序；`limit` 上限 1000。
- `title` 三路来源（见 §3.11）：宿主投影缓存 `session_projcache.json` → 会话 header 的 `title|name|summary|label` → 折叠出的**首条真实用户提问**（跳系统注入文本、截 60 字）；都没有则 `null`，界面回落成 `（无提问）· <短 id>`。
- `prompt` 是同一段提问的**片段**（≤200 字）：标题之外给搜索用；正文全文只在 `/session` 详情里给。
- `crossDays` = 首次与最近的**本地日历日**之差（同一天或时间缺失为 0），界面据此标「跨 N 天」。
- `models` 只给**前 5 个**（已按 tokens 降序）＋ 一行 `{ provider: "", model: "其它" }` 汇总长尾，避免长尾模型把响应撑大；**整行 `cost` 仍按全量模型算**，合并只影响展示。
- `archived` 来自宿主归档集合（`workspaceRegistry.archivedSessionIds`，取不到时读 `storages/workspace.json`）；**归档只标注不剔除**，统计口径不受影响。
- `workspace` 取 header 的 `cwd|workspace|workspacePath|projectPath|project`；缺失时 `null`，界面归到「未归属工作区」。
- `provider` 由模型归属键（如 `pi-ai/opencode-go/GLM-5.3-Flash`）归一得到，见 §3.9。

### 3.9 会话服务契约（`sessionPersistence`）

`src/server/sessions.ts` 只使用下面这组只读接口（0.2 形态），拿不到就降级：

```js
persistence.list()                // → [{ header, revision, eventCount? }]（本机实测不返回 eventCount）
persistence.open(id, "read")      // → handle
handle.read(0)                    // → { events }（offset 含 0；events[i].seq === i）
handle.inheritedEventCount        // fork 继承的事件数
handle.close()                    // 必须调用
persistence.identity              // 服务身份（换实例后缓存失效）
```

- **缓存**：命中 `(id, revision, eventCount)` 即跳过读取；`revision` 变化或服务身份变化时整段重折。
  ⚠️ 本机实测（133 个会话 / 2026-10-13）`list()` **完全没有 `eventCount` 字段**，因此缓存实际只由 `revision` 把关（记录里的 `eventCount` 恒为 `-1`，是无害的占位）。文档与代码都不要声称「eventCount 参与校验」。
- **首次折叠耗时分布**（同一语料实测，133 会话 / 119 MB / 14.4 万事件）：`list()` ≈ 3%、宿主 `open()` ≈ 78~82%（整段 zstd 解压 + JSON.parse，宿主主线程同步）、宿主 `read(0)` ≈ 17~18%（目录路径解析）、**插件自己的折叠 + 汇总仅 ≈ 1%（80~94 ms）**。所以插件侧优化的天花板很低；`sessions.ts` 用**并发 = 2**（>1 MiB 的会话仍串行）把 fs 等待叠起来，实测冷启动中位 6878 ms → 6174 ms（−10.2%，8/8 配对轮均更快）。并发不能调大：宿主冷读 memo 容量为 2（`COLD_LOG_MEMO_MAX_ENTRIES`），3 路并行会把先到的会话挤出 memo 反而整段重解压（实测慢 20%~45%）。回退开关是 `READ_CONCURRENCY = 1`。
- **继承前缀**：只把前缀里的 `request/header` 拿来做模型归属，不计入用量（与参考实现一致）。
- **上限**：一次最多折叠 80 个会话，按 header 的 `updatedAt|createdAt` 倒序取。
- **降级**：`sessionPersistence` 缺失 → `unavailable`；单会话 `open`/`read`/`close` 失败 → 丢弃该会话并计入 `partial`，绝不污染其它数据。
- 旧形态（`listSnapshots` + `readFrom` + 实时 `sessions.list()`）保留为回退路径，但未做真机验证。

### 3.10 会话事件的折叠口径（`session-usage.ts`）

- 用量样本来源：`assistant/chunk`（`data.chunk.type === "usage"`）、`assistant/message`（`data.usage`），以及 `assistant/message|assistant/attempt` 的 `data.stream[].chunk.usage`。
- 样本键：`turn:step`（缺 turn/step 时用 `seq`）。
- **同一键重复上报 = 覆盖**（不是累加）；`llm/retry-started` 之后同 `turn:step` 的样本属于**新一次尝试**，按新键累加。
- 模型归属：`data.message.source` → 回落最近一次 `request/header` 的 `data.header.config` → 都没有则 `unknown/unknown`。
- 每个样本记 `(day, hour, model, buckets)`，日/小时/模型三个维度的汇总由样本表派生，因此覆盖会同时修正日期与小时归属。
- 「调用次数」= 结算样本数（不是台账里的 `calls`）。
- **首条提问的取文本规则**（只影响「取哪条文本」，不改变标题优先级链）：跳过以 `<system-reminder` / `<system` / `<command-` / `<local-command` 开头的**宿主注入文本**（teammate 系统提示、斜杠命令回显、本地命令输出），取**下一条**人类消息；连续多条系统消息会一直往下找。折叠结果里保留正文全文（截断到 4000 字，详情抽屉用），列表标题截 60 字、搜索片段截 200 字。
- 全是系统消息（没有人类提问）时 `firstPrompt = null`，界面回落成「（无提问）· 短 id」，**不显示空标题**。

### 3.13 计费规则：三层价目（用户 YAML / 内置官方价目 / 聚合价）、`GET /dsh-key-usage/pricing` 与写入端点

> volatile 字段 / `ctx.configForms` / 插件页 `plugins.bundle.config` 配置卡片）**已整条退役**，
> 只在用户规则文件不存在时把旧版 entry config 的 `pricing` 当**只读回退**。
> 退役过程与旧链路的实测证据（宿主文件行号）保留在 [`05-后续版本计划.md`](./05-后续版本计划.md) §2.4，本节只写现状。

**三层价目 + 五层成本来源**

- **三层价目（价目数据的来源）**：内置官方价目（`pricing-catalog.yml`，CNY，见 §3.14）· 用户规则（`pricing-rules.yml`，本节）· LiteLLM 聚合价（随包快照 / 本机刷新副本，USD，见 §3.15）；
- **五层成本来源（逐格取值顺序，见 §4）**：`官方账单（台账 cost）> 你的规则 > 内置官方价目 > LiteLLM 聚合价 > 台账反推均价`，都没有显示 `—`。

**两个文件、两层 YAML 来源**

| 层 | 路径 | 谁写 | 读取方式 | 缺失 / 写坏时 |
| --- | --- | --- | --- | --- |
| 内置官方价目 | 随包发布的仓库根 `pricing-catalog.yml`（`pricing-catalog.ts` 用 `new URL('../pricing-catalog.yml', import.meta.url)` 定位 ⇒ **包根**） | 插件维护者（用户不要改，升级会覆盖） | 进程内只读一次（内容不随运行变化） | 文件缺失 ⇒ 该层整体失效（面板报「内置价目文件缺失」，成本只剩「你的规则 / 聚合价 / 台账均价」）；单条写法非法 ⇒ 只跳过该条 |
| 用户规则 | `$DSH_HOME/dsh-key-usage/pricing-rules.yml` | 面板保存（`POST`）、用户手改、agent 改 | **每请求读 + `mtimeMs:ctimeMs:size` 缓存**（带 ctime：同一毫秒内的同长度重写也能识别） | 文件不存在 = 空规则；解析问题带行号报 issue 并**跳过该条**，不影响其它条目与其它端点 |

- **生效时机**：改完用户规则文件**刷新页面即生效**，不需要重启宿主（写入端点会主动失效缓存，写完的同一请求就能读到新内容）；
- **来源优先级**（`rulesOrigin`）：`file`（用户 YAML）> `legacy`（旧版 entry config 的 `pricing`，只读回退）> `none`（还没有规则）；
- **成本取值优先级**另有一条（见 §4）：`官方账单 > 你的规则 > 内置官方价目 > LiteLLM 聚合价 > 台账反推均价 > —`（聚合价见 §3.15）。

**用户规则文件的字段表**

| 层级 | 键 | 必填 | 说明 |
| --- | --- | --- | --- |
| 顶层 | `rules` | 是 | 规则列表；也允许整份写成**裸列表**（省一层，手写更短） |
| 顶层 | `version` / `currency` | 否 | 格式版本（缺省 1）/ 文件默认币种（缺省 `CNY`） |
| 规则 | `provider` / `model` | 是 | 通道 id / 模型 id；`'*'` 表示任意通道 / 该通道全部模型（建议加引号，避免被当别名） |
| 规则 | `input` / `cacheRead` / `cacheWrite` / `output` | 是 | 四档单价；**缺一档整条跳过**（把缺档当 0 会静默算成免费） |
| 规则 | `unit` | 否 | `perMillionTokens`（缺省）/ `perThousandTokens` / `perCall`；写了非法值**整条跳过**（它决定数量级，不能猜） |
| 规则 | `currency` | 否 | 单条覆盖默认币种；跨币种不换算、不合计 |
| 规则 | `note` | 否 | 备注，界面原样显示 |
| 规则 | `offPeak` | 否 | 错峰：`windows` 列表 + 可选四档错峰价（缺档沿用标准价） |
| 窗口 | `from` / `to` | 是 | **本地时间** `HH:MM`；`from === to` = 全天，`from > to` = 跨午夜，`24:00` = 当天末尾 |
| 窗口 | `days` | 否 | ISO 星期 1=周一 … 7=周日；**缺省 / `[]` = 每天都适用**（与升级前保存的规则语义一致） |

- 顶层只认 `version` / `currency` / `rules`；规则级只认 `provider` / `model` / `unit` / `currency` / 四档单价 / `note` / `offPeak`；`offPeak` 只认 `windows` 与四档单价。
- **未知键 / 重复键只报 issue 不中断**（打错键名不能静默失效；重复键保留第一条）；**缺必填、单价非法、unit 非法则整条跳过**，条数超限只读前 200 条；匹配时同键规则只取第一条。
- `days` 非法值（越界 / 非整数 / 非列表）逐条报 issue 并容错为「每天」；`days` 没有任何有效值时报 issue 后同样按「每天」处理（不整段作废，避免金额突然变高）。
- `PRICING_MAX_RULES = 200`：超出只读前 200 条并报 issue（与写入端点的上限一致）。

**解析器是受限 YAML 子集**（`src/server/yaml-lite.ts`，内置价目与用户规则共用同一份）：

- 支持：注释、2 空格缩进映射、`- ` 块序列、单行标量（字符串 / 数字 / 布尔 / `null` / `~`）、行内 flow 序列 `[1, 2]` / `[]`、单双引号字符串、CRLF；
- **不支持**（一律**带行号报 issue**并跳过受影响内容，绝不静默错解）：tab 缩进、块标量 `|` / `>`、锚点 `&` / 别名 `*`、多文档 `---` / `...`、flow 映射 `{…}`、跨行 flow 序列、显式键 `? `、合并键 `<<`、缩进层级不匹配、引号未闭合；
- **没有引入任何第三方 YAML 库**：它也不用于 `cordis.yml` —— 那里有 `!!js` 表达式，只做文本提取（见 §3.2）。

**issue 形状**（`PricingIssue`，出现在 `/pricing` 的 `issues` 里）


`file` 取 `catalog`（内置价目）或 `user`（用户规则）；`line` 是 1 基行号，拿不到时为 `null`。

- 仅回环（非回环 403）；**只接受 POST**（其它方法回 `{ok:false,error}`）；body 上限 **256 KiB**；
- 请求体：`{ "rules": [ { "provider", "model", "currency", "input", "cacheRead", "cacheWrite", "output" } ], "currency": "CNY"? }` —— 客户端**只提交这 7 个字段**，`unit` / `offPeak` / `note` 不在请求里；
- **合并语义（冻结契约，`pricing-store.ts: mergeRulesForWrite`）**：按 `provider|model` 与**文件里现有条目**对齐 —— 旧条目的 `unit` / `offPeak` / `note` 保留，其余字段以请求为准、顺序按请求；删除靠「不在列表里」表达；
- 校验：`provider` / `model` 为 1–200 字符、币种非空、四档为非负数字（接受纯数字字符串）、同批 `provider|model` 不许重复、条数 ≤ 200；任一条不合格**整批拒绝**，不写半份文件；
- 返回**一律 HTTP 200**：`{ok:true, path, entries, issues}` 或 `{ok:false, error}`（中文原因可直接展示）；客户端只看 `ok` / `error`，不必区分状态码；
- 写入方式：只允许写 `pricing-rules.yml`（文件名 + 绝对路径双重校验，Windows 下大小写不敏感比较），同目录临时文件 + `rename` 原子替换，随后立刻失效读取缓存。

**⚠️ 面板保存会整份重写文件**：写出的内容是插件自己的头部注释 + 标准化后的条目，**用户手写的注释不保留**；只有条目字段按 key 继承（`unit` / `offPeak` / `note`）。所以「在 YAML 里用注释记价格出处」只在**没点过保存**时有效 —— 想留住就写进 `note` 字段，或先备份文件。

**界面表单只编辑五个字段**：通道 / 模型 / 币种 / 四档单价。`unit`、`offPeak`、`note` **只在 YAML 里维护**（列表对含这些字段的规则标出附加项，保存时按原值写回、不会清空；改通道 / 模型等于换主键，旧条目的这三项不跟过来）。旧版的「导入 / 导出 JSON」与 `catalog.templates` 下发已删除。

### 3.14 内置官方价目（`pricing-catalog.yml` ← `pricing-catalog.ts`）

用户不必手填规则也能拿到接近真实的金额：价目的**唯一事实来源是随包发布的仓库根 `pricing-catalog.yml`**
（`src/server/pricing-catalog.ts` 只读它、**进程内只读一次**、不写、不联网），**用户不要改它**（升级会覆盖；
要覆盖价格请写自己的用户规则文件，它优先于本文件），随插件发布即自动生效，
是「用户规则」之后、「聚合价」（§3.15）之前的第三级依据；文件缺失或某条写法非法时**带行号报 issue 并跳过该条**，
绝不猜单价。

| 项 | 约定 |
| --- | --- |
| 数据来源 | 各厂商**官方文档**（DeepSeek / Moonshot·Kimi / Z.ai / OpenRouter），逐条带 `source`（精确 URL）与 `fetchedAt` |
| 只写文档明确给出的价 | 文档没写的档位留空（折算为 0，**不用同类模型或输入价顶替**）；有歧义的一律不猜 |
| 币种 | 按文档原样记录，**不做任何汇率换算**（DeepSeek 取**中文文档**的 CNY；Kimi 为 CNY；OpenRouter / Z.ai 文档只有 USD）；金额按币种分行显示，不跨币种合计 |
| 匹配 | 精确 → 忽略大小写 → 去 `vendor/` 前缀（`deepseek/deepseek-v4.1-flash` → `deepseek-v4.1-flash`）→ 该通道通配；**不做模糊 / 近似匹配**，宁可继续显示「估算」 |
| 通配兜底 | 只有文档明确给出**该通道统一价**时才写 `provider + '*'` |
| 优先级 | 用户规则（`costSource: "rule"`）优先于内置价目（`"catalog"`）、内置价目优先于聚合价（`"aggregate"`）——用户显式表达过的意图优先于插件默认值，插件默认值优先于第三方聚合价 |

覆盖的通道与型号、四档价、错峰窗口与抓取日期，见 `docs/05-后续版本计划.md` 附录 A.5；
回归基线（迁移前后逐条等价）见 `test/fixtures/pricing-catalog.golden.json`。

### 3.15 LiteLLM 聚合价目（第三方、USD：随包快照 ← `data/litellm-model-prices.json` / `model-prices.ts`）

「内置官方价目」之后、「台账反推均价」之前的一层**真价格**：数据来自 [BerriAI/litellm](https://github.com/BerriAI/litellm)
的 `model_prices_and_context_window.json`（**MIT**，原文随包在 `data/litellm-LICENSE.txt`）。插件把上游文件**字节原样**放进包里，
运行时不联网、只在内存里建索引；来源 / commit / 抓取日期 / sha256 记在 `data/README.md`。

**三个上游地址（与 `model-prices.ts` 的常量一致）**

| 用途 | 常量 | 地址 |
| --- | --- | --- |
| 来源页（给人看 / 数据浏览） | `AGGREGATE_SOURCE_URL` | <https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json> |
| 刷新首选（raw） | `AGGREGATE_SNAPSHOT_URL` | <https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json> |
| 刷新备用镜像 | `AGGREGATE_MIRROR_URL` | <https://cdn.jsdelivr.net/gh/BerriAI/litellm@main/model_prices_and_context_window.json> |

**两份文件、一层来源**

| 层 | 路径 | 谁写 | 读取方式 | 缺失 / 写坏时 |
| --- | --- | --- | --- | --- |
| 本机刷新副本 | `$DSH_HOME/dsh-key-usage/model-prices.json` | 面板「刷新价目」（`POST /pricing/refresh`） | 每请求 stat（`mtimeMs:ctimeMs:size` 缓存；同一请求内 250 ms 不重复 stat） | 文件不存在 = 还没刷新过（正常）；不是合法 JSON / 没有可定价条目 ⇒ 记 issue 并**降级回随包快照** |
| 随包快照 | 包根 `data/litellm-model-prices.json`（`new URL('../data/litellm-model-prices.json', import.meta.url)` ⇒ 编译后从 `lib/` 的上一级解析） | 插件维护者（重新抓取步骤见 `data/README.md`） | 同上 | 缺失 / 写坏 ⇒ 该层整体失效（`loaded: "none"`），匹配一律不命中，**继续回落台账均价，绝不抛错** |

- **可定价条目口径**：排除顶层文档条目 `sample_spec`；只收 `mode` 为 `chat` / `completion`、且 `input_cost_per_token` 与 `output_cost_per_token` 都 **> 0** 的条目（图片 / 音频 / embedding / rerank 等没有可比口径，直接跳过）；模型名取键的最后一段并小写。当前随包快照按此口径是 **2697 条条目 / 1546 个模型名**（2026-10-14 复算；`test/model-prices.test.mjs` 用独立实现复算并要求规模达标）；
- **单位与币种**：上游是 USD / token，装载时 `×1e6` 换算成「每百万 tokens」后**原样并列**（`toPrecision(12)` 只抹浮点尾差）；**不做任何汇率换算**，聚合价规则带 `currency: "USD"`，与人民币价目**分别展示、不合计**；
- **缓存两档**：上游同时有 `cache_read_input_token_cost` 与 `cache_creation_input_token_cost` 时按原值收录；**只收录一档**时缺的那档按**未命中价**（`input`）代，并标 `partial: true`（界面在角标后加「· 部分」，tooltip 写「缓存写入价未收录，按未命中价计」）；两档都没有 = 该模型不支持缓存计价（0/0，**不标 partial**）；
- **匹配算法（冻结口径，`model-prices.ts: aggregateRuleFor`）**：模型名取键末段、查询串同样剥掉 `vendor/` 前缀后按小写比较 → 通道别名表命中（`deepseek-official → deepseek`、`moonshotai → moonshot | moonshotai`、`zai`、`openrouter`、`openai`、`anthropic`、`dashscope`、`azure → azure | azure_ai`、`google → gemini | vertex_ai`、`volcengine`）时，取「键里 `/` 段数最少 → 键名字典序」的第一条（`source: "alias"`）→ 别名不命中时**只有该模型名全库唯一才用**（`source: "unique"`），否则**跳过并记 `match-ambiguous`**（按 `provider|model` 去重、上限 200 条）—— **不猜通道**；
- **面板展示**（`PricingRulesPanel` 的聚合价目卡片）：装载来源（本地刷新文件 / 随包快照 / 未装载）、条目数、模型数、字节数、sha256、上游 commit（短写法 + tooltip 全值）、抓取时间、装载问题清单，以及「平时不联网：只有点『刷新价目』时才访问上游」的说明。

**`POST /dsh-key-usage/pricing/refresh`**（第二个写端点，也是**全插件唯一的价目联网入口**）

- 仅回环（非回环 403）；**只接受 POST**（其它方法回 `{ok:false,error}`）；**没有请求体**；
- 服务端 `refreshModelPrices()`：先 raw（`AGGREGATE_SNAPSHOT_URL`）、失败再试 jsDelivr 镜像（`AGGREGATE_MIRROR_URL`）；**两次尝试共享 20 秒总预算**（`AGGREGATE_REFRESH_TIMEOUT_MS`），单次响应上限 **12 MiB**（超限立即 abort），只发 `Accept: application/json`；
- **校验后才写**：响应要能 `JSON.parse` 成对象、每个条目的值都是对象、可定价条目数 ≥ 100，否则整次失败且**不覆盖**已有文件；通过后原子写（同目录 `.tmp` + rename）到 `$DSH_HOME/dsh-key-usage/model-prices.json`（写目标按文件名 + 绝对路径双重校验）并立刻失效装载缓存；
- 返回**一律 HTTP 200**：`{ok:true,url,bytes,entries,sha256,fetchedAt}` 或 `{ok:false,error}`（中文原因可直接展示）；
- **客户端超时 30 秒**（`src/client/api.ts: MODEL_PRICE_REFRESH_TIMEOUT_MS`）—— 必须大于服务端 20 秒预算，否则客户端会在服务端正要写盘时 abort，界面报「刷新超时」而文件其实已写成功；
- **不做开机拉取、不做定时轮询、不在别的端点里隐式联网**。

**对当前通道通常不产生新数字**：能命中的条目基本都被优先级更高的内置人民币官方价目覆盖，剩下的往往在 LiteLLM 里是多候选（按上面的「不猜通道」跳过）。它的作用是给**以后**新增的通道 / 模型兜底，不是给现有通道加价。

### 3.16 `GET /dsh-key-usage/session?id=<sessionId>`

单个会话详情（界面里点会话行打开的抽屉）。**只折叠这一个会话**：`sessionPersistence` 缓存里已折叠过就直接返回（零 I/O），
否则 `list()` 定位头部后单独 `open/read/close` 一次 —— 不会像 `/sessions` 那样重折全部会话。
整表折叠正在进行时先等它结束（宿主的解析 memo 只装 2 个会话，抢着 open 会把它挤掉）。

```jsonc
{
  "session": {
    "id": "session-43c91b48-…", "title": "开发 DSH Key 用量插件", "archived": false,
    "workspace": "D:\\EasyJob",
    "provider": "opencode-go", "providerLabel": "opencode-go", "costMode": "sub",
    "firstTime": 1791…, "lastTime": 1791…, "durationMs": 7200000, "crossDays": 1, "days": 2,
    "calls": 128, "tokens": 42000000,
    "buckets": { "inputTokens": …, "outputTokens": …, "cacheReadTokens": …, "cacheWriteTokens": … },
    "cacheHitRate": 96.2,
    "prompt": "首条真实提问全文（≤4000 字，超长截断）",   // 没有人类提问时为 null
    "models": [{ "provider": "opencode-go", "providerLabel": "opencode-go", "model": "GLM-5.3-Flash",
                 "tokens": …, "calls": …, "sharePercent": 82.4, "buckets": {…},
                 "cost": 12.3, "costSource": "rule" }],
    "hours": [{ "calls": 3, "tokens": 41000 }],   // 24 个槽；没有结算样本时为 null
    "cost": 13.54, "costSource": "rule"
  },
  "coverage": { "status": "complete", "reason": null },
  "priced": true
}
```

| 情况 | 响应 |
| --- | --- |
| 缺 `id` 参数 | `400 {"error":"缺少会话 id：请用 ?id=<sessionId>"}` |
| 不在宿主会话列表里 | `404 {"error":"会话不存在","id":"…","reason":"…"}` |
| 会话存在但读不出来 | `200` + 会话头字段（标题 / 工作区）与空用量，`coverage.status = "partial"`、`reason` 写明失败原因 |
| 宿主没有会话服务 | `200` + `coverage.status = "unavailable"`、`reason` 说明；不抛错、不影响其它端点 |
| 非回环 | `403 {"error":"loopback only"}`（与其它端点一致） |

- `hours` 是**一天里的哪个时段**的分布：跨天会话按小时累加（不是逐日序列），界面画 24 柱迷你图。
- `buckets.cacheWriteTokens` 只参与计费，不计入展示口径 `tokens`（口径见 §4）。
- 详情里的 `models` **不做**「其它」合并（只统计一个会话，长尾有限）；`cost` / `costSource` 与 `/sessions` 同一套取值（最弱的那一格）。

## 4. 统计口径（改动前必须确认）

| 指标 | 口径 | 位置 |
| --- | --- | --- |
| **Tokens（展示口径）** | `inputTokens + outputTokens + cacheReadTokens`，**不含** `cacheWriteTokens` 与 `reasoningTokens` | 客户端各处、`buildHeatmap`、`summarizeSession` |
| 命中率 | `cacheReadTokens / (inputTokens + outputTokens + cacheReadTokens)`，一位小数；**台账表与会话表同一公式**（截图里 3.82B / 3.96B = 96.2% 即此口径） | 客户端与 `cacheHitRateOf` |
| 调用次数 | 台账用 `calls` 原样；会话侧用**结算样本数**；展示时千分位用**空格**（`11 189`） | `fmtCalls` |
| 成本（台账） | `cost` 原样，`¥` + 两位小数；按计费模式区分「订阅内 / ¥0.00 / 无计费 / —」；角标 `官方` | `costCellText` |
| **成本优先级** | 台账当天的**官方成本**（`costSource: "official"`，不重算）> 用户规则（`"rule"`）> **内置官方价目**（`"catalog"`，随插件发布、自动生效）> **LiteLLM 聚合价**（`"aggregate"`，随包快照或本机刷新副本、USD）> 台账反推均价（`"estimate"`）> 无（`"none"`，界面显示 `—`） | `routes.ts: annotateCosts` / `pricing.ts: rowCostsOf` / `pricing-catalog.ts: catalogRuleFor` / `model-prices.ts: aggregateRuleFor` |
| 成本（会话 / 项目 / 按模型） | 用户规则优先，其次内置官方价目，再其次聚合价，都没命中回落 `buildPriceTable` 反推的均价：`Σ(输入×未命中价 + 缓存读×命中价 + 缓存写×写入价 + 输出×输出价) × 单位系数`；三者都没有返回 null → `—` | `pricing.ts: priceRowsByRules` / `ledger.ts: estimateCost` |
| 成本来源角标 | 每个成本单元格（总览 30 天、使用明细合计、会话、项目、按模型）标注 `官方 / 自定 / 官方价 / 聚合 / 估算`；只有真显示了金额（`¥…`）才挂角标，整天/整行取**最弱**的那一格（有一行回落均价就标「估算」）；命中聚合价且该条目缺一档缓存价时额外标「· 部分」 | `CostSourceChip.tsx` / `routes.ts: weakestSource` / `pricing.ts: weakestOf` |
| **缓存省钱** | `cacheReadTokens × (input − cacheRead) × 单位系数`，只统计命中价目（用户规则 / 内置价目 / 聚合价）的行，按价目币种分组 | `pricing.ts: priceRowsByRules` / `summarizeCoverage` |
| 错峰 | 窗口按**本地时间**判定（起止相同视为全天、`from > to` 视为跨午夜、`24:00` 为当天末尾），星期几同样取本地时间：每个窗口可带可选 `days`（ISO 1=周一 … 7=周日，**缺省 = 每天都适用**，保证升级前保存的规则行为不变）；非法 `days`（空数组 / 越界 / 非整数）容错为「每天」。日/会话级用量拿不到「模型 × 小时」拆分，**只有单日范围**用 24 小时槽算错峰占比加权（小时槽没有日期，带 `days` 的窗口在这里按「每天」近似），跨天一律按标准价 | `pricing.ts: isOffPeakAt` / `normalizeDays` / `offPeakTokenShare` |
| 规则匹配顺序 | 用户规则：`provider+model` 精确 → `provider+*` → `*+model` → `*+*`；同档内按规则声明顺序。内置价目更保守：精确 → 忽略大小写 → 去 `vendor/` 前缀 → 该通道通配；**不做模糊/近似匹配** | `pricing.ts: matchPricingRule` / `pricing-catalog.ts: catalogRuleFor` |
| 热力强度 | 客户端按可见区间的**活跃日五分位**自适应：< p20 少、p20~p40 较少、p40~p60 中、p60~p80 较多、≥ p80 多；活跃日不足 5 天时回落 1e7 / 3e7 / 6e7 / 1.5e8 绝对值 | `Heatmap.tsx` |
| 热力图窗口 | 近 9 个月（39 周，含未来格 ghost 占位）；固定 28px 方形格子，超出卡片宽度横向滚动；三类状态用同尺寸 + `inset box-shadow` 描边，避免大小不一 | `Heatmap.tsx` / `overview.module.css` |
| 会话标题 | 宿主投影缓存 → 会话 header 字段 → **首条人类提问**（跳过 `<system-reminder` 等系统注入文本，压平空白、截 60 字）→ 界面回落「（无提问）· 短 id」 | `session-meta.ts` / `session-usage.ts` / `SessionsTab` |
| 归档 | 仅标记不剔除：用量、项目聚合、热力图全部照常计入；会话列表默认隐藏，可切「全部 / 仅显示已归档」，显示时整行淡化 + 「已归档」小标 | `session-meta.ts` / `SessionsTab` |
| 按模型聚合 | `provider + model`，tokens 与命中率同会话口径；`lastTime` 是「用到该模型的最晚会话时间」**近似值**；`cost` 与 `/sessions` 同源（规则 → 内置官方价目 → 台账反推均价） | `modelRowsOf` / `ModelsTab` |
| 零 Token 行 | **不展示**：每日细目、按模型、项目用量、会话用量四处统一丢掉 `tokens === 0` 的行（只有调用数没有 Token，基本都是调用失败 / 未产生用量），列表底部写明隐藏条数；**服务端数据与合计不变**（合计里的调用次数仍含这些失败调用） | `rows.ts: dropEmptyRows` |
| 日期 | 台账键与小时槽都是**本地时间**；`resetsAt` 是 UTC ISO，界面统一显示为 `YYYY-MM-DD HH:mm` 本地时间 | `ledger.ts` / `fmtDateTime` |

> `cacheWriteTokens` 与 `reasoningTokens` 不计入**展示口径** tokens，但 `cacheWriteTokens` 参与计费
> （`/models`、`/sessions`、`/projects`、`/usage` 的 `models[].buckets` 都带它），页面底部「口径说明」已写明。

- **客户端 slot**：`sidebar.panellist`（导航项：宿主自持整行，插件只给图标 + `label` + `id`）与 `main`（同标识放在 `key` 上，宿主在主内容区渲染整页）。两者配对写法对齐已装的 dsh-context「上下文洞察」。历史方案（`settings.section`、`sidebar.footer.action`、`plugins.bundle.config` 插件页配置卡片）已弃用，理由与回退写法见 [`README.md`](../README.md) 的「入口位置与 slot 选择」。
- 开发时可用 **`link:` 协议**把仓库直接挂到 profile 上：`~/.dsh/profiles/<profile>/node_modules/dsh-key-usage` 变成指向仓库目录的 Junction（`dependencies.dsh-key-usage = link:<仓库路径>`），改动即时可见、不需要重装。安装命令与桌面端拦截规则见 [`README.md`](../README.md) 的「插件安装 / 卸载」。

| 改动 | 生效条件 | 实测状态（2026-10-13） |
| --- | --- | --- |
| `client/client.js` | 重新构建 + 刷新 GUI 页面 | 构建成功；页面需刷新（GUI 有鉴权，未做外部截图验证） |
| `lib/*.js`（服务端） | **退出并重开 DSH** | 插件在挂载时进入 Node 的 **ESM 模块缓存**：`remove` + `add` 重装后 `/sessions` 的行数上限仍是旧值（80），说明模块没有被重新导入。Hub `/restart` 在桌面端返回 `{ok:false, desktop:true}`，无热重载途径 |

**通道配置来源（易踩）**：`~/.dsh/profiles/desktop/cordis.yml` 是应用按需重写的**组合产物**——插件集变化期间会短暂变成空模板（实测 47,753 B → 223 B → 47,753 B）。所以 `loadChannels()` 先读 `cordis.yml`，取不到再回退到用户 patch 层 `cordis.patch.yml`（两者结构兼容，`test/routes.test.mjs` 覆盖了这条回退）。注意 patch 层的 `local` 通道不写 `apiKeyEnv`，因此判定顺序是「先本地端点、后未配置」。

## 6. 已知限制

1. 台账维度仍是「天 × provider × 模型」，**没有小时 / 项目 / 会话维度**；这三者改由宿主会话事件折叠得到（§3.9、§3.10）。两套数据源口径不同：同一枚数字在「使用明细」和「会话用量」里不保证相等，界面底部口径说明已写明。
2. `aggregateRange` 对无记录日期不补 0 行，客户端「按天 Tokens（N 天）」的 N 是**有数据的天数**，不是范围天数。
3. 客户端按 `provider` 过滤；原型演示数据用的是 `apiKeyEnv` 作为通道键 —— **真实链路以 provider id 为准**，不要照抄原型。
4. 会话事件里的 provider 可能是 pi-ai 路由名（`pi-ai/opencode-go`），`attributeModelKey` 按已知通道名在段边界从右往左匹配来归一；匹配不到就原样展示。
5. `sessionPersistence` 的 0.2 契约是按参考实现 + 离线夹具写的，**首次重启后需要真机确认**：`list()` 的 header 里是否真的带 `cwd` / `title`（缺了会全部落到「未归属工作区」），以及 `open/read/close` 的行为是否一致。
6. 会话折叠一次性最多 80 个会话、成本按台账均价估算，都是**有意的近似**，不是完整统计；`coverage` 字段会把不完整状态显式暴露给界面。
7. `/quota` 快照可能长期不更新（本机为 2026-09-30）；余额卡片现在会显示「快照时间」，但不会自动刷新宿主快照。
8. 错峰窗口支持可选 `days`（ISO 1=周一 … 7=周日，缺省 = 每天），因此「仅工作日」已能表达；DeepSeek 内置价目按「工作日三段 + 周末全天」配置，与官方「高峰只在周一至周五」一致。
9. **中国法定节假日仍表达不了**：插件没有节假日日历，DeepSeek 的 `note` 里已写明「节假日会按高峰价算」。偏差方向是把空闲当高峰 → **成本偏高**（保守），不会少算钱。
10. 错峰加权只用得上**单日范围**（`hours` 来自会话事件，且没有「模型 × 小时」拆分）；跨天与多日范围一律按标准价，属有意保守，不是遗漏。小时槽没有日期，带 `days` 的窗口在占比加权里按「每天」近似。
11. 规则写盘由插件自己完成（`pricing-store.ts` 原子写 `$DSH_HOME/dsh-key-usage/pricing-rules.yml`，临时文件 + 改名），**不再改 profile 的 `cordis.patch.yml`**；该文件是用户手改与面板保存的共同目标，并发手改时后写的一方会覆盖前一方（面板每次提交的是全部规则）。
12. 界面表单只编辑五个字段，`unit` / `offPeak` / `note` 只能改 YAML；含这些字段的规则在列表里会标出「只在 YAML 里编辑」，面板保存不会清空它们（`mergeRulesForWrite` 冻结契约，`test/client-pricing.test.mjs` 覆盖）。
13. 规则列表默认只显示 `cordis.yml` 里配置过的通道（`*` 通配规则始终显示），未配置通道的规则需要点「显示全部」；**过滤只是显示层**，成本与保存都不受影响。
14. **「跨币种不合计」目前只是口径原则，尚未在合计里强制**：`/usage`（`totalsOfMerged`）、`/summary`、`/sessions` 等处的合计仍是**按行直接相加**，同一格里理论上可能把人民币（内置官方价目 / 你的规则）与美元（聚合价）加到一起。这是**本批（0.1.7）之前就存在**的问题（内置 CNY 价目与 USD 价目本来就并存），本批没有让它变差；正确修法是「按币种分列小计」，已记为后续（`docs/05` §3 第 24 行）。按币种分组的字段（`coverage.ruleCostByCurrency` / `savingsByCurrency`）不受影响。
15. **聚合价这一层的覆盖是「有就好、没有就跳过」**：别名表只覆盖 10 个通道（见 §3.15），别名不命中且模型名不唯一时整条跳过（面板报 `match-ambiguous`，按 `provider|model` 去重、上限 200 条）；因此这一层对**当前**通道往往不产生新数字（能命中的都被更高层覆盖），它的价值是给以后新增的通道 / 模型兜底。随包快照会随上游改价而过期（面板显示装载文件的 mtime），要更新只能**手动点「刷新价目」**或重新抓取随包文件（步骤见 `data/README.md`）；上游结构变化时下载内容校验不过、**不会覆盖**已有文件。
