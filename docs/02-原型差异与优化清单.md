### 关于「把插件移到侧边栏」（第 10 条后半）

**结论（2026-10-13，两次纠正后定稿）：`sidebar.panellist` + `main` —— 导航列表里的条目 + 主区域整页内联渲染。**

```tsx
ctx.slots.inject('main', () => ctx.slots.register({ name: 'main', key: PANEL_ID }, UsagePage))
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({
  name: 'sidebar.panellist', id: PANEL_ID, order: 30, label: () => '使用情况',
}, (props) => h(UsageIcon, { size: props.size })))
```

- `sidebar.panellist` 由**宿主自持整行**（标签、hover/active 配色），插件只提供图标 + `label` + `id`；`main` 用**同一个值放在 `key`** 上，宿主按它渲染整页。这套配对写法与已装的 dsh-context「上下文洞察」完全一致。
- 条目落在导航组（插件 / 自动化任务 / 上下文洞察）之后、工作区之前；顺序由 `order` 控制。

走过的弯路（留档，避免下次再试）：

| 尝试 | 结果 |
| --- | --- |
| `settings.section` | 能显示，但设置页太挤 |
| `sidebar.footer.action` | 入口出现在侧边栏**页脚**（头像上方），且要做成浮层 —— 位置和交互都不是要的 |
| **`sidebar.panellist` + `main`** | 导航条目 + 整页，符合预期 |

端点已经与展示解耦，以上都只是客户端入口的差别，不需要动服务端。
