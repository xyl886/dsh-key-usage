## 1. P1 ── 提供商 API 契约汇总与兼容性加固

> 对应你的第 1 条。**这是后续所有计费/余额功能的地基**：先证明我们读得对，再谈读得准。

### 1.1 目标

把「我们实际调用 / 将来可能调用」的厂商接口，整理成一份**字段级契约**，并据此建立 fixture 与契约测试，让解析逻辑可以离线回归、字段漂移能被测试抓到。

### 1.2 覆盖范围

| 厂商 | 用途 | 现状 |
| --- | --- | --- |
| DeepSeek 官方 | 余额 + 定价（含缓存命中/未命中差异、是否错峰） | 已有 scheme，无 fixture |
| OpenCode / opencode.ai | 订阅窗口（rolling / weekly / monthly） | 已有 scheme，官方文档情况待确认 |
| OpenRouter | credits + **models 里的 pricing 字段**（天然的定价 API） | 已有 credits scheme，未覆盖 models |
| Moonshot / Kimi | 余额 + 定价页 | 已有 scheme，无 fixture |
| Z.ai / GLM | 余额 + 定价页 | 已有 scheme，无 fixture |
| 其它 OpenAI 兼容中转 | 有无余额/定价接口 | 无 scheme（需要时再补） |

> 详细的字段级契约（端点 / 鉴权 / 响应类型 / 单位 / 错误码 / 定价接口 / 文档链接）与**兼容性风险清单**由并行的调研产出，落地时并入本文件「附录 A」。

### 1.3 已经能预判的兼容性风险（按等级）

| 等级 | 风险 | 应对 |
| --- | --- | --- |
| 高 | 数值字段可能是**字符串**（余额常见 `"1.50"`），我们按 id 号处理 | 统一走 `textOf()`，同时接受 number / string |
| 高 | **200 但 body 是错误体**（部分中转商） | 解析后校验必填字段，缺失即判 `bad-json` 并回落快照 |
| 高 | OpenRouter 需要 **Management Key**，普通推理 key 会 401/403 | 文档里写明；错误文案区分「凭据被拒绝」与「权限不足」 |
| 中 | `balance_infos` 可能没有 CNY 项（或返回多币种） | 已有：优先 CNY，否则取第一项；补一条「无 CNY 时显示原币种」的提示 |
| 中 | 时间字段可能是 epoch 毫秒而非 ISO | `resetsAt` 解析同时接受 ISO 与数字 |
| 中 | 窗口缺项（没订某个周期） | 已有：缺项跳过；补测试覆盖 |
| 中 | 定价单位不同（元 / 千 token vs 百万 token） | 计费模型里显式存 `unit`（见 §2.3） |
| 低 | 限流（429） | 已有：按 `http-429` 回落；可加退避（非必须） |

### 1.4 测试方案（关键：**离线可回归**）

1. **fixtures**：`test/fixtures/providers/<provider>/<case>.json`，每个 case 存「原始响应 body + 期望解析结果」，全部脱敏（假 key、假数值）。
2. **契约测试**：`test/live-quota.test.mjs` 扩展成表驱动 —— 遍历 fixtures 调用同一解析路径，断言归一化结果（窗口键、百分比、币种、余额字段）。
3. **负例覆盖**：401/403、429、500、非 JSON、超大响应、字段缺失、类型漂移（string↔number）、空 `balance_infos`。
4. **字段漂移哨兵**：每个 fixture 记录「来源（文档链接 + 抓取日期）」；文档改版时人工更新 fixture，测试会立刻暴露解析不兼容。
5. **可选（需你授权）**：一次性真机校验脚本，用你本机凭据各打一次真实接口，把真实响应脱敏后固化成 fixture。**默认不做**，因为会联网 + 读凭据。

### 1.5 产出物

| 产出 | 位置 |
| --- | --- |
| 提供商契约汇总（总表 + 字段级 + 风险清单） | 本文件「附录 A」 |
| fixtures | `test/fixtures/providers/**` |
| 契约测试 | `test/live-quota.test.mjs`（扩展） |
| 解析容错改动（仅在测试暴露问题时才改） | `src/server/live-quota.ts` |

### 1.6 验收口径

- 风险清单里「高」级别的每条**都有对应测试**；
- 文档契约与 `live-quota.ts` 的实际解析逐字段对得上（附录 A 就是对照表）。

## 2. P2 ── 计费规则（✅ 已实现，未提交待验收；含内置官方价目）

> 对应你的第 2 条。目标：**成本从「估算」变成「有据可依」**，并且规则可见、可改、可追溯。
>
> **落地方式与本文原计划的四处差异**（实际以这一节为准）：
> 1. **UI 不新增 Tab**：并入「余额与配额」页下半部分（用户硬性要求）。插件页的 `plugins.bundle.config` 配置卡片只在 2026-10-13 那一轮存在过，已随「设置服务退役」一起**移除**（详见 §2.4）；
> 2. **重算在服务端**（原 §2.7 写的是「无需重启宿主：计费在客户端算」）：服务端每次请求现读规则文件参与成本估算，因此几个 Tab 天然一致，客户端不做二次计算；**2026-10-14 起规则本体是 `$DSH_HOME/dsh-key-usage/pricing-rules.yml`**（不再是宿主设置服务），每请求读 + mtime 缓存，改完**刷新页面即生效**，仍然不用重启宿主；
> 3. **台账当天的官方成本优先于用户规则**（本文原表把「用户规则」排在第一位）：官方账单金额是既成事实，用它反推/替换只会更不准；用户规则只作用在**没有官方数字**的地方。优先级最终为 **官方 > 用户规则 > 内置官方价目 > 台账反推均价 > 无**（内置价目见 §A.5，用户规则优先于它）；
> 4. **预算与告警整块移除**（2026-10-14 用户决定）：`/budget` 端点、客户端横幅、阈值配置与 `test/budget.test.mjs` 全部删除，见 §3 第 4 行。
>
> 实现位置：`src/server/pricing.ts`（纯函数）、`src/server/pricing-store.ts`（规则文件读写）、
> `src/server/yaml-lite.ts`（受限 YAML 子集解析）、`src/server/pricing-catalog.ts`（读包内 `pricing-catalog.yml`）、
> `src/server/routes.ts`（`/pricing` 读端点 + `POST /pricing/rules` 写端点 + 四处成本重算）、
> `src/client/tabs/QuotaTab.tsx` 下半部分 + `src/client/components/PricingRulesPanel.tsx`、
> 单测 `test/pricing.test.mjs` / `test/pricing-store.test.mjs` / `test/yaml-lite.test.mjs`（+ `test/routes.test.mjs`
> 的端到端断言）。完整的字段契约见 [`01-架构与数据契约.md`](./01-架构与数据契约.md) §3.13 与 §3.14。

### 2.1 为什么现在不准

现在的成本链是：台账里有官方成本 → 用它反推每个 `provider|model` 的均价 → 再乘会话 tokens。所以：

- 台账一停更（本机停在 2026-09-30），**所有新用量都没有官方成本**；
- 均价抹平了**缓存命中/未命中**的价差（DeepSeek 这两档差很多）；
- 错峰折扣、订阅制、赠送额度全都体现不出来。

### 2.2 数据来源与优先级

| 优先级 | 来源 | 获取方式 | 覆盖度 |
| --- | --- | --- | --- |
| 0 | **台账当天的官方成本** | 台账 `cost` 字段原样 | 仅台账覆盖期内（本机停在 2026-09-30） |
| 1 | **用户手填的计费规则** | 「余额与配额」页下半部分编辑；本体在 `$DSH_HOME/dsh-key-usage/pricing-rules.yml`（面板保存与手改写同一个文件，见 §2.4） | 任何厂商 / 自定义价格 |
| 2 | **内置官方价目**（✅ 已实现） | 随插件发布的静态数据（仓库根 `pricing-catalog.yml`，`src/server/pricing-catalog.ts` 只读它），**自动生效、不需要用户维护**；也可「下载规则模板」生成可编辑的等价用户规则 | 已收录 DeepSeek / Kimi / Z.ai / OpenRouter 共 18 条（见 §A.5） |
| 3 | **台账反推均价** | 已有 `buildPriceTable` | 台账覆盖期内可用 |
| 4 | 无 | 显示 `—` + 「未配置计费规则」入口 | — |

展示时必须标出来源：**官方（台账账单）/ 自定（你的规则）/ 官方价（内置官方价目）/ 估算（台账均价）**。

> **与本文原计划的差异**：原表把「厂商定价 API」写成运行时自动抓取。实际落地改为**静态内置价目**——
> 插件硬约束是「默认零外网」，运行时不抓价格；价目由维护者按官方文档人工更新并注明抓取日期。

### 2.3 计费规则的数据模型（字段契约）

下面这份 JSON 是**字段与语义的对照**（2026-10-14 起磁盘上存的是同一套字段的 YAML，见 §2.4）：

```jsonc
{
  "version": 1,
  "currency": "CNY",
  "rules": [
    {
      "provider": "deepseek-official",     // 通配 "*" 表示兜底
      "model": "deepseek-v4.1-flash",      // 通配 "*" 表示该通道全部模型
      "unit": "perMillionTokens",          // perMillionTokens | perThousandTokens | perCall
      "input": 2.0,                        // 未命中缓存的输入价
      "cacheRead": 0.2,                    // 命中缓存价
      "cacheWrite": 2.0,                   // 写入缓存价（没有就填 0）
      "output": 8.0,
      "offPeak": {                          // 可选：错峰折扣
        "windows": [{ "from": "00:30", "to": "08:30", "days": [1, 2, 3, 4, 5] }],   // days 可省 = 每天
        "input": 1.0, "cacheRead": 0.1, "cacheWrite": 1.0, "output": 4.0
      },
      "note": "来源：https://api-docs.deepseek.com/quick_start/pricing（2026-10-13）"
    }
  ]
}
```

- 匹配顺序：`provider+model` 精确 → `provider+*` → `*+model` → `*+*`（同档内按声明顺序）；
- `unit` 显式存，避免「按千 vs 按百万」错 1000 倍（缺省 `perMillionTokens`；写了非法值整条跳过，不按缺省硬算）；
- 每条规则带 `note`（来源链接），便于复核；
- **实现补充**：`offPeak.windows` 里的 `from`/`to` 是**本地时间** `HH:MM`，`from > to` 表示跨午夜，
  `24:00` 表示当天末尾，`from === to` 视为全天；每段窗口还可带可选 `days`（ISO 1=周一 … 7=周日，
  **缺省 = 每天**），用于表达「仅工作日 / 仅周末」；`perCall` 只用 `input` 档当每次调用价。

> **形状是冻结的**：顶层只认 `version` / `currency` / `rules`，规则级只认
> `provider` / `model` / `unit` / `currency` / 四档单价 / `note` / `offPeak`，`offPeak` 只认 `windows` 与四档单价；
> 多写键、缺档、类型不对都会**带行号报 issue 并跳过该条**，不会静默按 0 算成免费。

### 2.4 存储位置（**已定案：方案 Y —— 插件自己的 YAML 文件**，2026-10-14）

最初的三个候选（2026-10-13 评估）：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 宿主设置服务** | 走宿主的 `settings` / 客户端配置表单（dsh-context 用的 `plugins.bundle.config` 卡片就是这套） | 不直接写文件；跟宿主设置一起备份；在插件配置页可见 | 需要摸清宿主 settings API；跨 profile 不共享；题材被绑死在宿主配置链路上 |
| **B. 插件自己的文件** | `$DSH_HOME/dsh-key-usage/` 下的规则文件 | 简单、直观、跨 profile 共享；**agent 能直接改**（这才让「让 DSH 帮我配」成立） | 打破「不写文件」的旧约束（要写进 README / AGENTS 的权限说明） |
| **C. 只读 + 导入导出** | 规则只在界面上编辑，存在浏览器 localStorage；可导入/导出 JSON | 零写盘、零宿主依赖 | 换浏览器/清缓存就没了，不能多端共享 |

**2026-10-13 先按 A 落地，2026-10-14 用户改选方案 Y（B 的正式版）**：A 那套「不写文件」的好处抵不过它的代价 ——
规则进不了 agent 的手、宿主设置链路耦合重、卡片还占插件页。下面是那条**已退役链路**的实测结论，保留作复盘（不要再照着实现）：

| 环节（⛔ 已退役） | 当时的事实 | 证据 |
| --- | --- | --- |
| 命名空间 | 不是自取的名字，而是本条目在 profile 里的 id（`cordis.patch.yml` 的 `insert.id` = `dsh-key-usage`） | `dsh-settings/lib/index.js:432,443,502` |
| 可服务的前提 | 条目必须导出 schemastery 的 `Config` 且至少一个字段带 `.volatile()`；旧版 `settings.register()` 注册表已在宿主 0.1.7 移除 | `dsh-settings/lib/index.js:413-420,505-506,538-541`；第三方插件 `@liustack/modsearch` 的实测注释 |
| 客户端读写与卡片 | `ctx.configForms.get(条目 id)` 读写；`plugins.bundle.config` 槽按包名 keyed 渲染配置卡片 | `dsh-client-ui-settings/lib/client.js:1264-1349`；`dsh-client-ui-plugin-manager/lib/client.js:2522` |

⇒ 退役动作：`Config` / volatile 字段 / `configForms` / 插件页配置卡片 / 那轮 settings spike 全部删除。
跟随这个批次一起消失的还有 `src/client/pricingSettings.ts`、`src/client/components/PricingCard.tsx`、`src/server/schemastery.d.ts`；
settings 探针（`test/probe/`）也不再保留 —— 现在仓库里只有 `test/*.test.mjs` 与 `test/fixtures/`。`peerDependencies` 只剩 `@deepseek-ai/cordis`（optional）。

**方案 Y 的实际落地（现状）**

| 层 | 文件 | 谁维护 | 说明 |
| --- | --- | --- | --- |
| 内置官方价目 | 随包发布的仓库根 `pricing-catalog.yml` | 插件维护者 | 只读、不联网、不落盘；改价 = 改这个文件（升级会覆盖，**用户不要改它**） |
| 用户规则 | `$DSH_HOME/dsh-key-usage/pricing-rules.yml` | 用户 / agent / 面板 | 升级与重装都不丢；面板保存与手改是同一个文件 |

- **读取**：每个请求现读用户规则文件，按 `mtimeMs:ctimeMs:size` 做缓存 → 改完**刷新页面即生效，不需要重启宿主**；
- **写入**：`POST /dsh-key-usage/pricing/rules` 整批提交；服务端按 `provider|model` 从**文件里的旧条目**继承 `unit` / `offPeak` / `note`，然后**整份重写**（写插件自己的头部注释，**用户手写的注释不保留**）；只写这一个路径，同目录临时文件 + rename 原子替换；
- **旧配置回退**：旧版 entry config 的 `pricing`（`apply(ctx, config).pricing`）只作**只读回退**，用户规则文件一存在就不再使用，面板会显示来源是「旧设置服务里的历史值」；
- 字段表、issue 形状、优先级与端点契约见 [`01-架构与数据契约.md`](./01-架构与数据契约.md) §3.13、§3.14。

### 2.6 口径与展示规则

- 所有成本单元格统一带来源角标（`官方` / `自定` / `官方价` / `估算`；无依据时只显示 `—`，不挂角标）；
- 估算值在角标 tooltip 里说明依据（官方账单 / 你的规则 / 台账均价 / 无依据）；
- 多币种不换算、不合计：规则各按自己的 `currency` 算，面板上的金额按币种分行显示；
- **错峰**：规则表里标「错峰中」（按本地时间判定）；单日范围的成本按 24 小时槽的错峰占比加权。

### 2.8 风险（实现后复核）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 用户填错单价 | 金额直接算错 | 表单挡住「四档单价全 0」（会算成免费）；`unit` 写非法值整条跳过而不是按缺省硬算；「清空规则」回到内置价目与台账均价 |
| 规则与厂商调价脱节 | 数字过期 | 内置价目每条带 `source` + `fetchedAt`，面板显示「距今 N 天」、超过 90 天转警示；`note` 可写来源链接（只在 YAML 里维护）；模板与「让 DSH 帮我配」的提示词都要求核对官方定价页 |
| 写盘 | 插件现在会写文件（旧约束是「只写一个文件」） | 只写 `$DSH_HOME/dsh-key-usage/pricing-rules.yml`（写目标守卫按文件名 + 绝对路径双重校验），同目录临时文件 + rename 原子替换；写失败一律返回 `{ok:false,error}`，面板显式提示，不影响其它端点 |
| 面板保存整份重写 | 用户在 YAML 里手写的**注释不保留**（插件会写自己的头部注释），条目字段只按 `provider\|model` 继承 `unit` / `offPeak` / `note` | 面板上写明这一点；想留注记就把出处写在 `note` 字段里，或先备份文件再点保存 |
| 多币种 | 不同通道币种不同，合计会混 | 规则带 `currency`，跨币种不合计、分组显示 |
| 手改 YAML 写出不支持的语法 | tab 缩进 / 块标量 / 锚点别名 / flow 映射 / 多文档都不支持 | 解析器带行号报 issue 并**跳过该条**（不会静默错解），面板上能直接看到是哪一行；规则文件坏掉不影响其它端点 |
| 错峰只对单日生效 | 跨天没有小时分布 | 有意保守（按标准价），已在界面与 §2.7 写明；小时槽没有日期，带 `days` 的窗口在占比加权里按「每天」近似 |
| 规则文件被外部改动 | agent / 编辑器同时写同一个文件 | 读取按 `mtimeMs:ctimeMs:size` 判新旧；写入只允许回环请求、body 上限 256 KiB、请求先校验再落盘（不写半份文件） |

### A.2 需要修 / 需要标注的风险（按等级）
