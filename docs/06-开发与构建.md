## 其他安装方式

```bash
dsh plugin --profile web add github:xyl886/dsh-key-usage   # 从 GitHub 装（等价，包内含构建产物）
dsh plugin --profile web add link:/path/to/dsh-key-usage   # 本地开发：软链到仓库，改文件即时生效
dsh plugin --profile web remove dsh-key-usage              # 卸载（桌面端在 Plugin Hub 里操作）
```

桌面端直接改 profile 的依赖（CLI 被应用独占，只能用 DSH 自带的 pnpm）：

```powershell
$node = 'C:\Users\Lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$pnpm = 'C:\Users\Lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin\pnpm.mjs'
& $node $pnpm --dir "$env:USERPROFILE\.dsh\profiles\desktop" add dsh-key-usage
```

- 从 `link:` 切到 registry 版时，若 pnpm 报 `ERR_PNPM_EPERM`（无法创建符号链接），先把 `node_modules/dsh-key-usage`（junction）**改名让开**再安装 —— 原因是 pnpm 会试图导入旧链接内部的 peer 依赖。`peerDependencies` 现在只剩一个宿主提供的 `@deepseek-ai/cordis`（optional）；`@deepseek-ai/schemastery` 已随「YAML 是唯一事实来源」整块退役，全新安装不会再触发；
- 装完确认 `~/.dsh/profiles/desktop/package.json` 里 `dependencies.dsh-key-usage` 与 `dsh.profile.bundles` **两处都在**（pnpm 不维护 `bundles`）。

## 目录结构

```
src/client/   index.tsx（slot 注册：`main` + `sidebar.panellist`）· UsagePage / UsageIcon · KeyUsageSection（Tab 外壳）
              tabs/（6 个页面）· components/（含 PricingRulesPanel / CostSourceChip / TrendPanel / ShareBar）
              api.ts（取数封装 + 规则写盘 `POST /pricing/rules`）· export.ts（CSV / JSON 导出）
              pricing.ts（计费规则视图模型：类型 / 文案 / 模板与片段 / 提示词 / 价目新鲜度）· types.ts
              styles/（CSS Module，basename 全局唯一）
src/server/   index.ts（cordis apply；旧版 entry config 的 `pricing` 只作只读回退）
              routes.ts（10 个只读 GET + 1 个规则写入 POST；requireLoopback 拒绝非回环）
              pricing.ts（规则匹配 / 错峰 / 单位换算 / 缓存省钱）
              pricing-catalog.ts（读随包发布的 pricing-catalog.yml：内置官方价目 + 保守匹配，零外网）
              pricing-store.ts（pricing-rules.yml 读写 / 原子写 / 合并语义：保存不清空 unit / offPeak / note）
              yaml-lite.ts（受限 YAML 子集解析器：只认块映射 / 块序列 / 单行标量，绝不执行表达式）
              ledger.ts（台账）· collect.ts（通道判定）· merge.ts（台账 × 会话按天合并）
              live-quota.ts（官方余额实时查询 + 缓存）· quota-snapshots.ts（成功即落盘，失败回落）
              sessions.ts / session-usage.ts / session-meta.ts（会话折叠 / 标题 / 归档）
lib/ client/  构建产物（发布必须带，git 与 npm 都提交）
pricing-catalog.yml  随包发布的内置价目（运行必需，见「产物契约」与「计费规则的离线自检」）
```

## 产物契约（改这几处会踩坑）

- **客户端入口固定** `src/client/index.tsx` → 产物 `client/client.js`，必须是单文件 CJS + `window.__ModuleLoader__.load({ id, factory })` 头（`scripts/normalize-client-banner.mjs` 会校验并归一化 banner）。不要改 entry、产物名或加载方式；
- **`lib/` 与 `client/` 都要提交**：插件以包形态安装时宿主直接读这两个目录，CI 有一道闸会重新构建后要求 `git diff --exit-code`；
- **`pricing-catalog.yml` 必须随包发布**（`package.json` 的 `files`，与 `lib/` / `client/` 平级，不打进 bundle）：`lib/pricing-catalog.js` 用 `new URL('../pricing-catalog.yml', import.meta.url)` 定位它，也就是**包根**。缺了不会抛错，但内置价目这一层会整体失效，面板上会报「内置价目文件缺失」的 issue、成本只剩「你的规则 / 台账均价」两级。改价 = 改这个文件（`note` 里保留来源与日期）；
- 客户端构建必须**与机器无关**：`tsdown.config.ts` 用仓库相对路径做虚拟模块 id、并按字典序输出 CSS 导出表 —— 否则不同目录/不同机器构建出的 `client.js` 不一致，CI 的产物同步闸会失败；
- `tsc --noEmit` **不会**更新 `lib/`，而测试 import 的是 `lib/*.js` —— 改了服务端要先编译再跑测试；
- `cordis.yml` 是应用重写的组合产物，插件集变化期间会短暂变成空模板，因此通道提取会回退到 `cordis.patch.yml`。

## CI 与发布

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 push / PR 上跑 `pnpm run verify`，另加两道闸：

- **构建产物必须与源码同步** —— 重新构建 `lib/`、`client/` 后 `git diff --exit-code`；
- **发布包必须含三件套** —— `lib/index.js`、`client/client.js`、`cordis.patch.yml`。注意这道闸**不检查** `pricing-catalog.yml`，而它是运行必需项：发布前用 `npm run pack:dry` 的清单确认它在包里（`files` 已声明）。

发布是**人工触发**的独立工作流 [`.github/workflows/publish.yml`](../.github/workflows/publish.yml)：默认 `dry_run=true` 只校验打包，改成 `false` 才真正 `pnpm publish --provenance`。npm token 只放仓库 Secret `NPM_TOKEN`，本机不放；版本号在 1.0 之前一律走 `patch`。

## 更新界面截图（README 用）

README 的「界面预览」有 5 张图，放在 `docs/images/`，并**随发布包一起发**（在 `package.json` 的 `files` 里）。

1. **截图前打码**：工作目录 / 项目路径、金额、会话标题里的客户名等敏感信息一律遮掉；**不要**出现任何 Key、token、`Authorization`、cookie；
2. **用演示数据截，不要用真实数据** —— 真实数据截完必须打码，容易漏；需要造数据时用本地 mock 注入（**mock 代码与数据不要提交进仓库**，跑完即撤）；
3. **保持与现有 5 张一致**：同一主题（浅色）、窗口宽度约 1500 px（README 里统一按 820 px 显示），文件名沿用 `usage-overview.png` · `usage-daily.png` · `按模型.png` · `项目总量.png` · `usage-quota.png`；
4. **换图后同步三处**：README「界面预览」小节的 `<img>`（含 `alt` 与下面那行 `<sub>` 说明）、`package.json` 的 `files`（新增文件名必须加，否则发布包里缺图）、以及本节的文件名清单；
5. **自查**：README 里每个 `src="./docs/..."` 都真实存在；`npm run pack:dry` 的清单里能看到这几张图（实测 2026-10-14：`npm pack --dry-run` 报 **27 个文件**，含 `pricing-catalog.yml`）。

## 计费规则的离线自检

计费规则改为「YAML 是唯一事实来源」后，自检全部落在**仓库内的测试与夹具**上：不读宿主实现、不联网、不改文件。

```bash
node test/yaml-lite.test.mjs        # 受限 YAML 子集：合法写法，以及 tab / 块标量 / 锚点 / 多文档必须报 issue
node test/pricing-store.test.mjs    # pricing-rules.yml 读写：原子写、合并语义、字段校验、写目标守卫
node test/client-pricing.test.mjs   # 客户端视图模型：五字段表单、模板 / 片段 / 提示词文本、提交字段
node test/pricing.test.mjs          # 匹配优先级 / 错峰 / 单位换算 / 缓存省钱 + 内置价目回归基线
node test/routes.test.mjs           # 端点契约（含 POST /pricing/rules 的请求校验与写盘）
```

- `test/fixtures/pricing-catalog.golden.json` 是**内置价目迁移的回归基线**：`pricing-catalog.yml` 逐条解析结果必须与它深度相等，同时断言该文件确实随包发布（`test/pricing.test.mjs`）；改价目时这份 golden 要同步更新，否则测试会挡住。
- 旧的 `test/probe/asar_extract_schemastery.mjs`、`test/probe/dsh_settings_schema_probe.mjs` 已随宿主设置服务链路**一起删除**（本仓库已没有 `test/probe/`），不要再按旧文档去跑。
