## 其他安装方式

```bash
dsh plugin --profile web add github:xyl886/dsh-key-usage   # 从 GitHub 装（等价，包内含构建产物）
dsh plugin --profile web add link:/path/to/dsh-key-usage   # 本地开发：软链到仓库，改文件即时生效
dsh plugin --profile web remove dsh-key-usage              # 卸载（桌面端在 Plugin Hub 里操作）
```

桌面端直接改 profile 的依赖（CLI 被应用独占，只能用 DSH 自带的 pnpm）：

```powershell
$node = 'C:\Users\Lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$pnpm = 'C:\Users\Lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin\pnpm.mjs'
& $node $pnpm --dir "$env:USERPROFILE\.dsh\profiles\desktop" add dsh-key-usage
```

- 从 `link:` 切到 registry 版时，若 pnpm 报 `ERR_PNPM_EPERM`（无法创建符号链接），先把 `node_modules/dsh-key-usage`（junction）**改名让开**再安装 —— 原因是 pnpm 会试图导入旧链接内部的 peer 依赖；
- 装完确认 `~/.dsh/profiles/desktop/package.json` 里 `dependencies.dsh-key-usage` 与 `dsh.profile.bundles` **两处都在**（pnpm 不维护 `bundles`）。

## 目录结构

```
src/client/   index.tsx（slot 注册 + configForms 接线）· UsagePage / UsageIcon · KeyUsageSection（Tab 外壳）
              tabs/（6 个页面）· components/（含 PricingRulesPanel / PricingCard / CostSourceChip / TrendPanel）
              export.ts · pricing.ts + pricingSettings.ts（计费规则视图模型与读写通道）
              styles/（CSS Module，basename 全局唯一）
src/server/   index.ts（cordis apply + 计费规则的 Config）· routes.ts（9 个只读端点）
              pricing.ts（规则匹配 / 错峰 / 单位换算 / 缓存省钱）
              pricing-catalog.ts（内置官方价目：纯静态数据 + 保守匹配，零外网）
              ledger.ts（台账）· collect.ts（通道判定）· merge.ts（台账 × 会话按天合并）
              live-quota.ts（官方余额实时查询 + 缓存）· quota-snapshots.ts（成功即落盘，失败回落）
              sessions.ts / session-usage.ts / session-meta.ts（会话折叠 / 标题 / 归档）
lib/ client/  构建产物（发布必须带，git 与 npm 都提交）
```

## 产物契约（改这两处会踩坑）

- **客户端入口固定** `src/client/index.tsx` → 产物 `client/client.js`，必须是单文件 CJS + `window.__ModuleLoader__.load({ id, factory })` 头（`scripts/normalize-client-banner.mjs` 会校验并归一化 banner）。不要改 entry、产物名或加载方式；
- **`lib/` 与 `client/` 都要提交**：插件以包形态安装时宿主直接读这两个目录，CI 有一道闸会重新构建后要求 `git diff --exit-code`；
- 客户端构建必须**与机器无关**：`tsdown.config.ts` 用仓库相对路径做虚拟模块 id、并按字典序输出 CSS 导出表 —— 否则不同目录/不同机器构建出的 `client.js` 不一致，CI 的产物同步闸会失败；
- `tsc --noEmit` **不会**更新 `lib/`，而测试 import 的是 `lib/*.js` —— 改了服务端要先编译再跑测试；
- `cordis.yml` 是应用重写的组合产物，插件集变化期间会短暂变成空模板，因此通道提取会回退到 `cordis.patch.yml`。

## CI 与发布

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 push / PR 上跑 `pnpm run verify`，另加两道闸：

- **构建产物必须与源码同步** —— 重新构建 `lib/`、`client/` 后 `git diff --exit-code`；
- **发布包必须含三件套** —— `lib/index.js`、`client/client.js`、`cordis.patch.yml`。

发布是**人工触发**的独立工作流 [`.github/workflows/publish.yml`](../.github/workflows/publish.yml)：默认 `dry_run=true` 只校验打包，改成 `false` 才真正 `pnpm publish --provenance`。npm token 只放仓库 Secret `NPM_TOKEN`，本机不放；版本号在 1.0 之前一律走 `patch`。
