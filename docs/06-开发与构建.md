# 开发与构建（深度附录）

> 常用命令、「改动生效条件」与验证安装见 [`../README.md`](../README.md) 的**开发**一节。

## 其他安装方式

```bash
dsh plugin --profile web add github:xyl886/dsh-key-usage   # 从 GitHub 装（包内含构建产物）
dsh plugin --profile web add link:/path/to/dsh-key-usage   # 本地开发：软链到仓库，改文件即时生效
dsh plugin --profile web remove dsh-key-usage              # 卸载（桌面端在 Plugin Hub 里操作）
```

- 桌面端 CLI 被应用独占，只能改 profile 依赖：`& $node $pnpm --dir "$env:USERPROFILE\.dsh\profiles\desktop" add dsh-key-usage`（`$node` / `$pnpm` 用 DSH 自带运行时路径，见 [`AGENTS.md`](../AGENTS.md)）。
- 从 `link:` 切到 registry 版若报 `ERR_PNPM_EPERM`，先把 `node_modules/dsh-key-usage`（junction）**改名让开**再装 —— pnpm 会试图导入旧链接内部的 peer 依赖。装完确认 `~/.dsh/profiles/desktop/package.json` 里 `dependencies.dsh-key-usage` 与 `dsh.profile.bundles` **两处都在**（pnpm 不维护 `bundles`）。

## 目录结构

```
src/client/   index.tsx（slot 注册：`main` + `sidebar.panellist`）· UsagePage / UsageIcon · KeyUsageSection（Tab 外壳）
              tabs/（总览 / 使用明细 / 项目用量 / 按模型 / 会话用量 / 余额与配额）
              components/（Heatmap / TrendPanel / CostSourceChip / DailyDetailTable / SessionDetailDrawer …）
              api.ts（取数封装 + 价目刷新 `POST /pricing/refresh`）· currency.ts（显示币种与折算，金额渲染唯一收口点）
              export.ts（CSV / JSON 导出）· pricing.ts（价目展示工具与类型）· types.ts
              styles/（CSS Module，basename 全局唯一）
src/server/   index.ts（cordis apply）
              routes.ts（12 个只读 GET + 1 个写 POST（价目刷新）；requireLoopback 拒绝非回环）
              pricing.ts（价目匹配 / 错峰 / 单位换算 / 缓存省钱）· pricing-catalog.ts（读随包 pricing-catalog.yml）
              model-prices.ts（LiteLLM 聚合价的装载与匹配 + 刷新）· fx-rate.ts（汇率查询与缓存）
              yaml-lite.ts（受限 YAML 子集解析器，只用于内置价目）
              ledger.ts（台账）· collect.ts（通道判定）· merge.ts（台账 × 会话按天合并）
              live-quota.ts（官方余额实时查询 + 缓存）· quota-snapshots.ts（成功即落盘，失败回落）
              sessions.ts / session-usage.ts / session-meta.ts（会话折叠 / 标题 / 归档）
lib/ client/  构建产物（发布必须带，git 与 npm 都提交）
pricing-catalog.yml  随包发布的内置价目（运行必需）
data/         随包的第三方价目快照（运行必需）：litellm-model-prices.json（字节原样）+ litellm-LICENSE.txt + README.md
```

## 产物契约（改这几处会踩坑）

- **客户端入口固定** `src/client/index.tsx` → 产物 `client/client.js`，必须是单文件 CJS + `window.__ModuleLoader__.load({ id, factory })` 头（`scripts/normalize-client-banner.mjs` 会校验并归一化 banner）。不要改 entry、产物名或加载方式；
- **`lib/` 与 `client/` 都要提交**：插件以包形态安装时宿主直接读这两个目录，CI 有一道闸会重新构建后要求 `git diff --exit-code`；
- **`pricing-catalog.yml` 与 `data/` 必须随包发布**（`package.json` 的 `files` 已声明，与 `lib/` / `client/` 平级，不打进 bundle）：两者都用 `new URL('../…', import.meta.url)` 从包根定位。缺了不会抛错，但对应的价目层整体失效（内置价目缺失 → 成本只剩「聚合价 / 台账均价」；聚合价缺失 → `aggregate.loaded = "none"`）。改价 = 改 `pricing-catalog.yml`；改快照后要同步 `data/README.md` 的「字节数 / sha256 / upstream commit / 抓取日期」四行；
- **快照按二进制存**：`.gitattributes` 里 `data/litellm-model-prices.json -text` 不做任何换行转换，否则 Windows 的 `core.autocrlf` 会改字节、sha256 对不上；
- 客户端构建必须**与机器无关**：`tsdown.config.ts` 用仓库相对路径做虚拟模块 id、按字典序输出 CSS 导出表，否则不同机器构建出的 `client.js` 不一致，CI 的产物同步闸会失败；
- `tsc --noEmit` **不会**更新 `lib/`，而测试 import 的是 `lib/*.js` —— 改了服务端要先编译再跑测试；
- `cordis.yml` 是应用重写的组合产物，插件集变化期间会短暂变成空模板，因此通道提取会回退到 `cordis.patch.yml`。

## CI 与发布

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 push / PR 上跑 `pnpm run verify`，另加两道闸：**构建产物必须与源码同步**（重新构建后 `git diff --exit-code`）与**发布包必须含三件套**（`lib/index.js`、`client/client.js`、`cordis.patch.yml`）。第二道闸**不检查** `pricing-catalog.yml` 与 `data/`，而两者都是运行必需项 —— 发布前用 `npm run pack:dry` 的清单确认它们在包里。

发布是**人工触发**的独立工作流 [`.github/workflows/publish.yml`](../.github/workflows/publish.yml)：默认 `dry_run=true` 只校验打包，改成 `false` 才真正 `pnpm publish --provenance`。本机发布：`npm version patch --no-git-tag-version` → `npm publish`，发布前跑完 `verify` / `pack:dry`。

**npm token 管理**：一个 token 只干一件事 —— 发布用 Granular token 只勾 `dsh-key-usage` 包、`Read and write`、勾 Bypass 2FA、90 天有效期；撤回 / 删版本另建一个**不勾 Bypass 2FA** 的 token 临时用（`npm unpublish` 需要它 + `--otp=`）。值只放本机 `~/.npmrc`（600）或 CI Secret `NPM_TOKEN`，绝不写进仓库；怀疑泄露时**先 Revoke 再改密码**。`npm unpublish` 是破坏性操作，官网「Delete package」删的是整包并锁 24 小时，单版本撤回只有 CLI 支持。

## 更新界面截图（README 用）

README 的「界面预览」有 5 张图（`usage-overview.png` · `usage-daily.png` · `按模型.png` · `项目总量.png` · `usage-quota.png`），放在 `docs/images/` 并随发布包一起发（`package.json` 的 `files`）。

- **截图前打码**：工作目录 / 项目路径、金额、会话标题里的客户名一律遮掉；**不要**出现任何 Key、token、`Authorization`、cookie；
- **用演示数据截**，不要用真实数据；造数据的 mock 代码与数据**不要提交进仓库**；

## 离线自检

自检全部落在**仓库内的测试与夹具**上：不读宿主实现、不联网、不改文件。

```bash
node test/yaml-lite.test.mjs        # 受限 YAML 子集：合法写法，以及 tab / 块标量 / 锚点 / 多文档必须报 issue
node test/pricing.test.mjs          # 价目匹配 / 错峰 / 单位换算 / 缓存省钱 + 内置价目回归基线
node test/model-prices.test.mjs     # 聚合价目：条目数 / 模型数、装载优先级、别名与多候选匹配、partial、刷新校验
node test/fx-rate.test.mjs          # 汇率：上游成功 / 超时 / 非 200 / 坏 JSON / 缓存命中与过期 / 默认兜底 / 写盘守卫
node test/client-pricing.test.mjs   # 客户端价目展示工具与币种折算
node test/routes.test.mjs           # 端点契约（含 POST /pricing/refresh 与 GET /fx、/rates）
```

- `test/fixtures/pricing-catalog.golden.json` 是**内置价目的回归基线**：`pricing-catalog.yml` 逐条解析结果必须与它深度相等，同时断言该文件确实随包发布（`test/pricing.test.mjs`）；改价目时同步更新，否则测试会挡住；
- `test/model-prices.test.mjs` 直接读**真实的随包快照**，因此它同时是「快照没被换行转换弄坏」的哨兵：sha256 要与文件本体、`data/README.md`、测试里的硬编码锚点三处一致。
