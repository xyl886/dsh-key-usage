# 更新记录

版本号规则：1.0 之前一律走 `patch`；**只有作者的发布指令才推动版本号**，未发布期间 `package.json` 的 `version` 保持不变，各批改动合并记在下一节里。

> 0.1.0 ～ 0.1.2 是发布当日的快速迭代，此处只记要点；逐条改动见仓库提交历史。发布时间取自 npm registry。

## [0.2.3] —— 2026-10-30

### 变更

- **概览 KPI 重做（十张卡）**：成本 / Tokens / 输入 / 输出 / 缓存读 / 缓存命中率 / 日均 Tokens / 日均成本 / 调用次数 / 会话数。每张卡统一为「图标 + 标签 → 上期值与环比同一行 → 大数」；环比由**上一等长窗口**重算并跟随通道 / 模型筛选（成本类上涨标警示色、下降标绿，命中率用 pp）；「缓存节省」从卡片区移出，改为「日均 Tokens」。
- **会话数 KPI 修复**：概览可见时后台懒加载会话段（不占首屏），计数改成「会话首末时间与窗口有交集」，不再长期显示 `—`。
- **概览·使用趋势按范围换粒度**：今天 → 24 根小时柱、7 天 → 28 根 6 小时柱，其余仍按天；脚注改为「活跃 N 个时段 · 最忙 {时间}」，悬停标签带日期（`10-30 14时`），「全部」仍是年热力图。
- **`/usage` 新增 `hoursByDate`**：按日期 × 小时下发 calls / tokens / 输出 / 缓存读 / 会话数 / 成本；成本按该小时逐模型套价目（错峰按星期几 + 小时判定），并带逐币种小计。窗口超过 120 天不下发，避免响应过大。
- **明细·分时成本**：范围=今天时画 24 根小时柱、=7 天时画 28 根 6 小时柱，标题切换为「分时成本」；「会话」档在分时与按天两种粒度下都有数（按天用「当天有活动的会话数」），不再恒为 `—`。
- **概览·按时段**：标题旁加「长期」标签，明确它是长期画像、不随范围切片。
- **工具页**：趋势直接使用 `/tools` 返回的窗口内按天数据，随范围变化。
- **测试**：`test/routes.test.mjs` 覆盖 `hoursByDate` 的小时桶（调用数 / 会话数 / token 合计）。
## [0.2.2] —— 2026-10-30

### 变更

- **筛选成为全局唯一入口**：七个区块全部跟随顶部范围/日期与通道/项目/模型筛选。概览 KPI 在筛选激活时改由过滤后的数据计算（不再读 summary 月列）；会话页接时间范围（按会话首末时间与窗口求交）与通道；分布页接通道（面板金额与占比按所选通道重算）；额度页跟通道（只显示所选通道的卡片）。
- **工具页跟随筛选**：新增 `GET /tools?from&to&project&model`，折叠时按会话保留工具统计（不重读会话），窗口按天切片；索引缺失返回 `null`，客户端回落快照全量。
- **提问页跟随筛选**：新增 `GET /prompts?from&to&project&model&provider`，复用折叠时的按天词桶，套用同一组筛选并按同长度前段算环比；上期无数据时四个 `prev*` 为 `null`。
- **使用趋势按范围换粒度**：今天按小时（24 桶），7 天按 6 小时 × 7（28 桶），其余按天；「会话」档改由会话首末时间逐日折算（此前取不到字段、恒为空）；排行的「还有 N 个」可点开完整弹窗。
- **按时段补全四档**：`heatmap` 段新增 `hourlyMetrics`（每格 calls / tokens / sessions / cost，旧的纯调用数矩阵保留兼容）。会话数按「该小时有调用的去重会话」计；费用按该小时逐模型套价目计算，**错峰按星期几 + 小时判定**，无价目依据记 `null`（界面 `—`）。为支撑这一档，折叠层每小时的桶新增 `sessions` 与逐模型 token 桶。
- **界面向宿主看齐**：页面标题 20/500/28、外壳单层内边距 28/48、内容列 960 居中、分区标题 14/500/22、辅助文字 13、控件 36 高 12 圆角、分段控件统一为「无底槽 + 28 高药丸 + 400 字重 + 淡灰选中」；新增 `scripts/check-ui-scale.mjs`（刻度越界与「状态类未挂基础类」都会让 `verify` 失败）。修掉明细页指标 tab 选中态丢基础类、露出浏览器默认按钮边框的问题。
- **浮层交互**：三组筛选下拉互斥（同时只能开一个），切区块时自动关闭；自定义日期时胶囊高亮。
- **存储 schema 3**：新增统一元信息表 `app_meta(scope, key, value, version, source, updated_at)`，`meta` / `litellm_meta` 在打开库时迁移进来（旧表双写一轮，下一版删除）；价目快照元信息补 `bytes / sha256 / fetchedAt / upstream`。`fx_rate` 保持独立强类型表；界面文案仍走 `client/core/copy.ts`（不进库）。
- **文档与测试**：契约新增 §3.22 存储层；`test/db.test.mjs` 覆盖 schema 2 → 3 迁移与幂等；`test/routes.test.mjs` 覆盖 `hourlyMetrics` 四档。
## [0.2.1] —— 2026-10-30

### 变更

- **顶部工具栏与筛选**：工具栏（标题 / 范围 / 日期 / 三组筛选 / 区块导航）整块吸顶；范围改分段控件，自定义起止换成日历区间选择器（先点起再点止、区间连片、未来日期禁用、Esc 关闭）；通道 / 项目 / 模型三组筛选支持搜索、全选、清空与多选，选项按 Token 用量降序；默认「分页」，可切「滚动」整页铺开。
- **区块定名**：额度 / 概览 / 明细 / 分布 / 会话 / 工具 / 提问（原「额度与订阅 / 使用明细 / 工具与技能 / 提问词云」）。
- **概览 KPI 拆成六张**（本期成本 / Tokens / 缓存命中 / 缓存节省 / 会话 / 日均），成本与日均带上期环比；额度卡正文按内容排布不再被网格拉伸；明细合计只要有金额就显示（含未定价行时标「部分」）。
- **提问页**：词表移除，词云逐词悬停显示次数与占比，四张 KPI 补上期环比（近 30 天 vs 紧邻前 30 天，服务端按天分桶精确切窗）。
- **设置弹窗**：显示 / 价目 / 关于合并为「设置」一个 tab；日志改平铺列表、消息与详情直接展示（无展开），保留级别 / 来源筛选与搜索。

- **「使用情况」重排为七个区块**：额度与订阅 → 概览 → 使用明细 → 分布 → 会话 → 工具与技能 → 提问词云。默认「滚动式」整页铺开、导航跟随滚动高亮，勾「分页」回到一次一个区块；额度与订阅提到最前。
- **额度与订阅改卡片式**：网格按宽度自适应（320px 起）、每卡正文固定三行等高；opencode-go 三个窗口一行进度条 + 重置时间，DeepSeek 只列总余额 / 充值 / 赠送（不再用进度条表达余额）；新增通道多选下拉，勾掉的不显示（选择存本地，新通道默认可见）。
- **概览**：KPI 跟随页面范围；使用趋势指标可切（活跃度 / Token / 输出 Token / 缓存读 / 调用 / 费用），范围=全部时改用**年热力图**（53 列 × 7 行，月份轴按周列精确定位、放不下就跳月不叠字），其余范围仍是柱状图；项目 / 模型排行指标可切；「按时段」7×24 矩阵按调用数着色。
- **使用明细**：上半是每日成本面板（费用 / Token / 输出 Token / 会话 × 合计 / 日均 / 峰值），下半是逐日明细（按天 / 按通道 / 按模型，表头排序、行内 ▸ 展开模型、环比、来源列中文化）。
- **分布**：Mekko（块宽 = 成本占比，宽块补模型 top2 的 Token 占比）、缓存节省、Token 构成、通道成本；提问词云与词表拆到独立的「提问词云」区块（4 KPI + 词表 + 导出 CSV）。
- **会话只列主会话**：榜单 / 形态 / 会话列表都剔除子代理会话（子代理不单独占行，父行标「N 子会话」、详情抽屉里仍可展开）；范围下拉两档「全部会话 / 隐藏已归档」，归档只影响列出的行、不动统计数字。
- **新增「工具与技能」区块**：服务端在原有的一次会话遍历里解析 `tool/call` 事件，统计工具调用 Top7（技能取 `skill` 的参数、MCP 取 `mcp_call` 的 server 并归并 `mcp__server__tool` 写法）+ 近 7 天趋势；快照新增 `tools` 段（全量历史），无数据时为 `null`、界面显示「暂无采集」。
- **页头与字号**：范围改成分段控件，自定义起止只在选中「自定义」时出现且日期框压到 22px；刷新周期下拉（默认 30 秒，可关）；字号统一为正文 13 / 区块标题 15 / 数字 18，页内不再有 <12px 的小字。
- **提问词云改成真分词（jieba-wasm）**：中文从「滑动 2-gram」换成 jieba —— 「数据库」「结构设计」「成本计算」「画蛇添足」整体成词，不再出现「据库 / 库表 / 表结」这类碎片；英文仍走原标识符正则 + 停用词表，注入段清洗与虚词边界过滤不变。懒加载（构建会话数据时预热一次，wasm 与词典初始化约 270 ms；宿主启动路径不加载），加载失败静默回退 2-gram。jieba-wasm@2.4.0 是 MIT、只作服务端依赖：wasm 由安装方解析，npm 包体积不变（1.4 MB）。
- **存储改为单个 SQLite 库（`usage.db`）**：快照按「段」存、LiteLLM 价目拆成行级表（构建时只查命中的模型，不再每次解析 2.7 MB）、系统日志进 `log_entry`（保留 30 天，替代 JSONL + 512 KB 截断）、汇率与历史配额种子各一张表。驱动 `node-sqlite3-wasm`（MIT，wasm 1.3 MB，由安装方按 dependencies 解析、不进 tarball）—— 插件服务端跑在宿主 Electron 里，原生 sqlite 模块 ABI 不匹配，`node:sqlite` 在 Node 22 需实验 flag。
- 首次启动自动迁移：旧 5 个文件导入后移入 `.trash`；端点响应结构一字未改，客户端零改动。

## [0.1.9] —— 2026-10-23

### 变更

- **打开页面不再干等重建（体验修复）**：原先首屏 `GET /snapshot?fresh=1` 会让服务端同步重算一次（实测 20 小时内 180 次重建，单次 123–3242 ms、中位约 1.3 s，冷启动更久），打开页面就是干等这几百毫秒到几秒。现在改成两段式：先取本机快照**立即渲染**，紧接着再取 `fresh=1` 重算并替换；追取次数 6 → 2。
- **首屏请求从 5 个降到 1 个**：`/pricing` 与 `/usage` 此前在挂载时无条件拉取（`/pricing` 服务端还会 `sessionSources.collect()` 全量扫一遍会话），现在 `/pricing` 整个请求删掉（它的唯一消费者是个死组件 `PricingInfoBlock`），`/usage` 只在切到「使用明细」时才取。
- **总览删字**：热力图 7 项图例（无数据 / 当日无用量 / 五档词）整体删除 —— 颜色深浅自明、档位含义进悬浮；「类型」列只放计费模式，未配置通道不再在这里显示「未配置 API Key」（改由整行变灰 + 状态点表达）。
- **热力图可点进明细**：点某一天的格子 → 切到「使用明细」并定位到那一天（原来只有悬浮）。
- 随本批清掉的死代码：死组件 `PricingInfoBlock`（含 13 个只为它加的词典键）、通道详情里依赖 `/pricing` 的「价目 N 天未更新」一行与相关取值、39 个死键（词典 407 → 368）、17 个死 CSS 类（含被删图例的 `.ghost`）。
- **界面干爽化（用户逐条反馈）**：配额卡的「实时 / 刚刚」删掉，通道卡那行「数据时间 X · 本机快照 · 实时查询未成功 + 查看系统日志」整行删掉，非实时值不在版面提示（时间与失败原因只记系统日志，点页头日志图标可查）；「暂无价格依据（本通道与同名模型都没有官方价目）」→「暂无价格依据」；各页脚注（模型 / 会话 / 明细）与空态长句收进「口径」弹窗或简化成「—」；
- **页头收敛成「刷新 + 设置」**：币种切换只留 ¥ / $ 两个符号；「刷新汇率」「刷新价目」与汇率来源时间一起移进新的**设置弹窗**（页头齿轮）；
- **控件尺寸统一**：按钮 / 下拉统一 30px 高、8px 圆角、1.05 字号，日期范围分段按钮 24 + 2×2 + 2×1 = 30px → 视觉齐平；会话页搜索框定宽 220px，修掉「导出 csv / json 被挤到第二行」；
- **控件尺寸真的统一了（按验收意见返工）**：上一版只在文件末尾追加同名选择器覆盖，尺寸其实还是三套（按钮 8px/1.05×、下拉与搜索框被覆盖成 6px/1×、日期分段按钮组 36px）。现在规格只写在主规则上：按钮 / 下拉 / 搜索框 / 导出按钮统一 **30px 高、8px 圆角、1.05 字号、左右 10px**；日期分段按钮组 = 24 + 2×2 + 2×1 = **30px**，与同排控件齐平；
- **「实时 / 刚刚」彻底清干净**：「最近活跃」列改成本地时间（今天 `HH:mm`，更早 `MM-DD HH:mm`），不再出现「刚刚 / N 分钟前」；单价表表头不再拼 `1 USD = 6.70 CNY · 缓存 · 时间`（换算说明只留在设置弹窗）；
- **「快照」小标签只留时间**：悬浮里不再搬那整句「数据时间 X · 本机快照 · 实时查询未成功」，只给时间，原因本来就在系统日志里（点标签即开）；
- 顺带按验收清单清掉：不可达的「配额整页」分支（Tabs 里早就没有入口）、零引用的 `overviewCaptionOf`、本次改出的死 CSS（`fxHint` / `aggregateStatus*`）与整份无人 import 的 `trend.module.css`；补上服务端会发但词典缺失的 `issue.channels-failed` / `issue.quota-refresh`（英文模式不再回落中文并记缺词）；环形图悬浮不再把名字印两遍；分布页在「按项目筛选」时图模式也显示筛选条（可一键清除），并给成本占比补一句口径说明（只统计有价目的行）；
- **通道详情：单价表的「来源」列改成「成本」并与「用量」换位**：现在是 `… 输出 | 用量 | 成本`，成本 = 该行这段用量按**表里同一份「此刻单价」**算出的金额（`/rates` 新增 `cost` / `costCurrency` 字段），有价目就显示金额（只有**聚合价**才挂来源角标），没有价目依据仍是「无依据」（服务端给 null，不猜、也不显示 ¥0.00）；
- **清死代码 114 处**：词典删 70 个没人引用的键（477 → 407，含历史 Tab / 环比 / 相对时间词的残留）、CSS 删 44 个没人用的类（7 个文件，删完 11 个 css 文件「类数 == 在用数」）；`quota.sourceLabel` 本来是候选，查证后仍在用（日志的「来源」筛选、单价来源提示）故保留；
- **价目信息块的 12 行中文字面量走词典**（此前英文模式下会显示中文）；新增 13 键、删掉随之变死的 5 键；
- 日志面板的**复制 / 导出只作用于当前筛选结果**（顶部条数就是筛选后的数量，两者对得上）；导出时间戳改成确定性本地格式；
- 构建耗时那条 issue 记 `info` 而不再记 `warning`：它每 5 分钟一条，会把日志面板的「警告」档刷满；
- **按页懒加载**：`GET /snapshot?sections=a,b,c` 只裁剪下发（构建仍是全量一份），首屏只取总览需要的段，切 Tab 再取那段；客户端只把这次真的带回来的段合并进内存状态（段为 null 时不覆盖，避免构建失败把已加载的数据清空）；落盘仍是全量一份；
- **「项目用量」与「按模型」合并成「分布」页**（5 个 Tab → 4 个）：顶部 `按项目 / 按模型` 切换，默认图表优先 —— 两张**环形占比图**（Tokens 占比 / 成本占比，纯 SVG 无依赖；每卡前 8 段 + 其余并成「其它」，中心显示占比最大的一段，每一段可悬浮看名称 / 金额 / 占比）；成本占比只收「表里真的显示金额」的行（订阅 / 免费 / 无计费不计），权重用 `comparableMoneyOf`（混币种又没汇率时该行不参与，不按 0 摊也不猜汇率）；表格默认收起，展开后仍是原来那两张表（筛选 / 排序 / 导出 / 点位联动一个不丢）；
- **分布页定稿（按用户验收反馈）**：Tokens 卡从「按模型」改成「按通道」（此前两张 Tokens 图同源重复，合计完全一致）；环形图不再排图例 —— 悬停某段时**中心显示该段名称与占比**、移开恢复总计；**点某段下钻**到明细表并定位（项目 / 模型 / 通道三个维度都能筛，「其它」这类合并段只展开不定位）；词云布局按 words 记忆（螺旋 + 碰撞检测不再每帧重算），配色从三档深浅改成 **8 色按排名轮换**，前 6 名加粗；图表区标注「统计范围：全部历史」（与「近 30 天」的页面口径不同）。
