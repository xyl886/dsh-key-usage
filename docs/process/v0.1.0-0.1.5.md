# 02 · 原型差异与优化清单

> 状态：已完成（2026-10-13 三轮实施）｜ 原型 [`prototype/key-usage-settings-prototype.html`](./prototype/key-usage-settings-prototype.html) 是**设计意图**，不是现状；数字与当前实现不可直接对照（原型用演示数据、通道键是 env key）。

## 1. 已实施的差异

2026-10-13 三轮反馈全部落地，要点：

- **入口**：从设置页迁到 `sidebar.panellist`（导航条目）+ `main`（主区域整页），页面组件不绑定具体 slot；
- **总览**：Key 清单按「通道（状态点 + 名）/ 类型 / 今日 / 近 30 天 / 余额或窗口 / 30 天成本 / 明细 →」重排；补分组标题、hover 反馈、三态区分（未配置 / 已配置无用量 / 有用量）；成本按计费模式显示「订阅内 / ¥0.00 / 无计费 / 金额」；
- **服务端补字段**：通道状态 `status`（ok / warn / danger / off）与计费模式 `costMode`，判定集中在 `collect.ts: classifyChannels`；总览的两段聚合走 `/summary`；
- **热力图**：近 9 个月（39 周）固定 28px 方形格 + 横向滚动，三类状态同尺寸（`inset box-shadow` 描边），五档图例（含 ghost / 无用量），按**活跃日五分位**分档；
- **使用明细**：4 张统计卡（第 4 张是占比卡）、卡片副文案、范围文案、按天柱状图 x 轴标签、空态与加载 / 失败区分、单日范围自动切 24 小时（数据来自会话事件并标注来源）；
- **余额与配额**：状态点 + 「provider · 计费方式」副标题、按原因分档的空态文案、余额字段固定顺序、重置时间统一 `YYYY-MM-DD HH:mm`、快照时间与「已 N 天未更新」提示；
- **代码健康**：tooltip 改 React 节点渲染（不再拼 HTML）、折叠行 `<Fragment key>`、取数收敛到外壳（首屏不再并发两次 `/usage`）、死代码与 `--dsw-text-2` 笔误清理。

**余额「不是实时」的争议**（原第 9 条）：当时确实只读宿主旧快照；现在允许「查余额 / 配额」「刷新价目」「刷新汇率」三个**显式联网动作**，凭据仍只走宿主 `credentials` seam（见 [`AGENTS.md`](../AGENTS.md) 硬约束）。

## 2. 有意保留的差异

| 项 | 取舍 |
| --- | --- |
| 缓存读配色 | 用半透明强调色（原型是实心色）—— 暗色主题下层次更清楚 |
| 图表 tooltip | 保留 Top5 模型列表（原型只有汇总）—— 信息更多 |
| 刷新按钮 | 仍一次性重拉台账类端点、按需重拉会话数据（原型按 Tab 重渲染） |
| 默认范围 | 保留「近 30 天」（原型默认今日） |
| 热力图格子 | 不可点击（与原型一致） |

## 3. 走过的弯路（留档）

| 尝试 | 结果 |
| --- | --- |
| `settings.section` | 能显示，但设置页太挤 |
| `sidebar.footer.action` | 入口落到侧边栏**页脚**（头像上方），且只能做成浮层 |
| **`sidebar.panellist` + `main`** | 导航条目 + 整页，最终形态（对齐已装的 dsh-context「上下文洞察」） |

入口位置与展示解耦，改入口不需要动服务端；`main` 用与 `sidebar.panellist` 的 `id` 相同的值放在 `key` 上配对。

# 03 · 按 Tab 拆分重构（已实施）

> 状态：已实施（2026-10-13）｜ 起因：「`KeyUsageSection.tsx` 太长，按 Tab 拆成每 Tab 一个 tsx？」

## 结论与结果

**要拆，但不能只按 Tab 拆**：Tab 不是最大的块 —— 只按 Tab 拆完，`DetailTab` 仍有 ~350 行。真正该抽的是**热力图、每日细目表、tooltip** 三块，Tab 拆分只是外层。

| 项 | 结果 |
| --- | --- |
| 外壳 | `KeyUsageSection.tsx` 由 728 行 / 39.3 kB 降到 ~210 行 / 7.3 kB（只留 Tab 路由、取数、范围与筛选状态、页脚） |
| 拆分 | 外层按 Tab；内层抽 StatCard / ShareCard / Heatmap / TokenBars / DailyDetailTable，另加 `format.ts` / `channels.ts` / `api.ts` / `tooltip.tsx` |
| 样式 | `styles/{shared,overview,detail,lists,quota}.module.css`，basename 全局唯一 |
| 顺手修 | 折叠行 React key、首屏重复 `/usage`、tooltip 的 `innerHTML`、死代码与 `--dsw-text-2` 笔误 |
| 验收 | `tsc --noEmit` 通过；客户端构建 112.39 kB 且 banner 校验通过；离线测试全绿 |
| 未做 | 浏览器实测（需重启宿主后回归） |

## 两个必须记住的约束

- **CSS basename 全局唯一**：`tsdown.config.ts` 的样式去重键是 `插件id/文件basename`，不同目录下的同名 `*.module.css` 会让后一个**静默不注入**（`styles/overview.module.css` ✅ / `styles/index.module.css` + `tabs/index.module.css` ❌）；CSS Modules 类名带哈希前缀，**类名不能跨文件复用**，共享样式放 `shared.module.css` 并各自 import。
- **构建契约不变**：entry 仍是 `src/client/index.tsx`，产物仍是单文件 `client/client.js`，所有新文件都打进同一个 bundle。

## 有意的取舍

- 跨组件通信沿用 **props 下发**（层级只有一层，不引入 context）；
- 需要跨 Tab 保留的状态（范围、筛选、展开、排序）留在外壳，不下沉；
- 执行顺序：外移纯函数 → 抽内部组件 → 抽 Tab → 拆样式，每步只做一类改动，构建后逐 Tab 回归（纯搬运也容易改错三元判断）。
