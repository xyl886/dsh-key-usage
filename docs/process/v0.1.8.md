## 本版做了什么

- **系统日志落盘**：`src/server/data/log-file.ts` → `$DSH_HOME/dsh-key-usage/plugin.log`（JSONL、追加、超 512 KB 只留后半段、写目标双重校验）；端点 15 → **17**（新增 `GET|POST /dsh-key-usage/log`）。刷新页面后仍能查上次为什么失败。
- **失败原因只进日志**：页面上只剩一行「结论 · 查看系统日志」（`components/LogHint.tsx` + `requestOpenLog()`）；日志窗支持刷新 / 复制 / 导出 `.txt` / 清空、条目展开详情、失败条目重试。
- **会话名与子代理判定改走宿主投影**：名字取 `storages/session_projcache/sessions/<id>.json` 的 `record.rows.title.val`，按 id 惰性读 + mtime 缓存（首次全量约 331 ms，之后每次只 stat 约 16 ms）；子代理只有 `record.rows.subagent.val.identity` 存在才算（续接会话不再被误藏）。实测 4 个会话改判主会话，默认视图可见数与侧边栏一致。
- **项目 = 宿主工作区**：行骨架改用工作区表（名字用 `title`），不在表里的历史目录合并成一行「未归入工作区」（本机 9 行 → 5 行）；`ProjectRow` 增加 `workspaceTitle` / `paths` / `registered`。
- **界面去重**：删「另有 N 个子代理 / 已归档会话未显示」两行、「跨 N 天」、通道详情 7 处重复表达；占比条不再单列明细（悬停外侧弹一个 tip）。
- **自定义范围改日历弹层**（新增 `components/ui/DateRangePicker.tsx`）。
- **英文残留中文（第二批）**：服务端下发的 `costLabel` / `windowLabel` 改走词典键；三页计数、会话抽屉、通道详情、口径弹窗长句入词典。
- **测试**：新增 `test/log-file.test.mjs`（10 项）、`test/client-log.test.mjs`（9 项），`routes` / `session-meta` / `pricing` / `model-prices` / `client-pricing` 扩充；测试文件 15 → 17。
- **工程**：修掉 publish 工作流的「假成功」（`dry_run` 传字符串时两个分支都不执行却报 success）。
- **文档**：`docs/` 根目录去掉序号编排（`01-架构与数据契约.md` → `架构与数据契约.md`、`06-开发与构建.md` → `开发与构建.md`），`04-归档会话的影响与对策.md` 的结论并入契约 §3.11 与 AGENTS 硬约束后移除；清掉两条指向已删文档的失效链接。本批再按两层价目同步 AGENTS / 契约 / 开发与构建 / README。

### 后来这批（2026-10-16）

- **打开页面即最新（用户要求：汇率与 LiteLLM 除外）**：`GET /snapshot?fresh=1` 成为页面打开入口 —— 本地段距上次重建 ≥ **10 秒**（`SNAPSHOT_OPEN_MIN_MS`）就**阻塞**重算一次（只算本地，不联网），配额段距上次查询 ≥ **60 秒**（`SNAPSHOT_QUOTA_TTL_MS`）就**后台**补查一次（不阻塞首屏，返回体标 `quotaRefreshing: true`，客户端 1.5 秒后追取、最多 6 次）。补查走 `force: false`，由 `live-quota` 的 60 秒缓存做第二道闸门。`open` 是新的构建来源（`buildSource`）。**取证**：原来的 `view({ backgroundQuota: true })` 从未被任何调用点传过（`git log -S` 查证），「页面打开超 10 分钟 TTL 后台补查」一直是死代码 —— 打开页面既不重算本地段、也不查配额，余额可能是几小时前的值。

- **计价口径改两层（用户拍板）**：`通道内价目`（内置官方价目按 provider + model 命中 → `costSource: 'catalog'`；否则 LiteLLM 聚合价按**通道别名**命中 → `'aggregate'`）→ `同模型官方价目`（本通道没有价目时，聚合价里该模型名**全库唯一**命中 → 新增 `'model'`；同一厂商的 `x` 与 `vendor/x` 两条同价键算唯一；同名候选跨多个厂商时用**内置价目里该模型的厂商**当通道兜底再查一次）；两层都不命中即 `'none'`，界面显示 `—`。强弱序 `SOURCE_RANK = { official: 0, catalog: 1, aggregate: 2, model: 3, none: 4 }`。
- **台账反推均价整层删除**：不再有 `'estimate'`；`AveragePrice` / `AveragePriceLookup` 类型、`ledger.ts` 的 `buildPriceTable` / `estimateCost` / `PriceEntry`、`rowCostsOf` / `summarizeCoverage` 的均价回调全部移除。用户原话：内置价目「有没有都无所谓，因为已经内置了 LiteLLM 计费规则」—— 内置价目现在只是「通道内价目」的来源之一，缺了不影响插件工作。
- **计价实测**：`opencode-go` + `moonshot-v1-8k`（别名不命中、聚合价同名唯一）→ `model` / USD 0.2；`opencode-go` + `deepseek-flash`（同厂商同价双键）→ `model` / USD 0.3；`opencode-go` + `glm-5.3-flash`（10 条跨厂商候选，内置价目知道厂商 `zai`）→ `model` / USD 0.15；`opencode-go` + `gpt-5.4-mini`（跨厂商、价不同、内置价目不认识）→ `none`；`deepseek-official` + `deepseek-flash` 仍是 `catalog` / CNY。`match-ambiguous` issue 改由 `matchPricedRule` 在最终定不下来时记（纯匹配器不记），避免「报了已跳过却又有金额」。
- **接口与词典同步**：`/pricing` 覆盖度的 `averagedModels` → `modelModels`；`/rates` 的 `source` 取值改为 `catalog | aggregate | model | none`；客户端 `CostSource` 同步五档，词典键 `cso.model` / `csh.model` / `source.model`（值「模型官方价」）取代 `cso.estimate` / `csh.estimate` / `source.estimate`（`srv.ratesAverage` 删除）。
- **移除会话数上限**：`src/server/data/sessions.ts` 的 `MAX_SESSIONS = 200` 删除（用户明确要求）—— 以前超出 200 个会话的部分会**静默退出**会话 / 项目 / 模型统计，出现「数字凭空变小」；现在宿主 `list()` 返回多少就折多少。
- **一次构建只读一遍会话**：`routes.ts` 的 `builders.local` 先 `collect()` 一次，再喂给 `modelsPayload` / `projectsPayload` / `sessionsPayload`（此前三个段各自 `collect()`，同一次构建把宿主会话列表与变更会话读三遍，实测 p50 3.3 s、最高 13.8 s）。
- **会话读取明细落盘**：`createSessionSource` 新增 `stats()`，返回 `{ sessions, cached, read, listMs, readMs, totalMs }`；每次本地重建以 `info` 追加进 `$DSH_HOME/dsh-key-usage/plugin.log`（消息「本地重建：会话读取明细」），**不进 `issues`**（避免界面弹警告）。
- **首开不再等构建**：`snapshot.ts` 的 `view()` 在构建进行中不再 `await waitForIdle()`，直接把手上一份（标 `building: true`）返回 —— 以前首开要干等 1～14 s（实测）。
- **构建耗时阈值 2000 → 4000 ms**（`SNAPSHOT_SLOW_BUILD_MS`）：实测 54 次采样里 42 次超 2000 ms，日志被这条刷满；明细已经每次落盘，阈值只留给「真的慢」。
- **日志去重落盘**：客户端 `core/log.ts` 的同一条目**只落盘一次**，重复出现只在内存累加 `×N`（以前每次重复都写一条一模一样的记录）。
- **5 个宿主未声明令牌修掉**：`--dsw-alias-bg-mask` → `bg-mask-1`、`fill-l1` → `interactive-bg-hover`、`fill-l2` → `interactive-bg-active`、`state-danger-primary` → `state-error-primary`、`state-warning-primary` → `state-warn-primary`（这 5 个在宿主 CSS 里只被 `var()` 引用、从未声明，真机取空值）。新增 `scripts/check-design-tokens.mjs`（`npm run check:tokens`，已挂进 `verify`）：插件 CSS 用到的令牌逐个在宿主归档里核对，实测当前 **17 个全部命中**；找不到宿主归档时只提示并退出 0，所以 CI 上安全。
- **打包修正**：`package.json` 的 `files` 里 `CHANGELOG.md` 改成 `docs/CHANGELOG.md`（原来指向不存在的路径，发布包实际不含更新记录）。
- **界面小项**：会话页归档三档筛选记住上次选择（localStorage，键 `dsh-key-usage-archive-filter`，隐私模式下按默认档）；项目页「未归入工作区」那行可展开 / 收起目录清单（新词典键 `p.pathsOpen` / `p.pathsClose`）。

## 实测后决定不做

- **快照瘦身**：`snapshot.json` 实测 **226 KB**，其中 sessions 段 **168 KB** —— 看着很大，但每行平均 **1.0 KB**，逐模型明细已被 `SESSION_MODEL_ROWS = 5` 合并（164 行只有 201 条模型行，平均 1.3 条/行），把上限再降没有收益。把 `models` 从快照里摘掉、改成展开时按需拉，会破坏「统一快照是唯一数据来源」这条硬约束，还要让每次展开多一次请求 —— **不值得，保持现状**。真要动体积，先看有没有新的实测依据。
