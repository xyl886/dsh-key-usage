## 无价目文案与 i18n 的连带修复

`'暂无价格依据（本通道与同名模型都没有官方价目）'` 这个长句**不在** `serverText` 的映射表里，英文界面下会原样透出中文；改成短句后命中 `srv.ratesNone`，顺带修好。

## 这一批（2026-10-21）：首屏懒加载 + 总览删字

用户原话：「你还是没有搞懒加载，页面所有数据都是一次性渲染，体验极差」。核实后确认**只做了数据分段、没做请求时机**：挂载时 `/pricing`、`/usage` 无条件拉取，首屏 `fresh=1` 还要同步等一次重建（日志实测 180 次/20 h、单次 123–3242 ms）。

- 首屏两段式：本机快照立即渲染 → 后台 `fresh=1` 重算替换；追取 6 → 2 次；
- 删 `/pricing` 请求（唯一消费者是死组件 `PricingInfoBlock`，整块删除）；`/usage` 只在切到明细时取；
- 热力图图例 7 项全删；「类型」列只放计费模式；点热力图格子跳明细并定位到该日；
- 死代码：`PricingInfoBlock` + 13 个只为它加的键、通道详情的「价目 N 天未更新」行、39 个死键、17 个死 CSS 类；
- 文档：`AGENTS.md` 的「打开页面阻塞重算」硬约束改成两段式表述（仍是「打开页面必定拿到最新数据」，只是先出旧的一版）。

## 待办（下一批候选）

- 通道详情单价表的「成本」列用的是**当前时刻**的单价乘这段用量（单价列与成本列永远对得上）；错峰时段看到的金额会与按天加权的结果不同，这是有意口径；
- 通道详情弹窗（`QuotaTab`）里的「价目装载详情」还占版面，可折叠进设置或默认收起；
- `ShareBar` 组件没有真正复用（它的 props 绑死了 `UsageResponse`）；分布页已改用自带的 `PieChart`（环形图），`ShareBar` 仍服务于按模型 / 项目的表格页；
- 分布页表格收起会卸载内部组件，重新展开时两张表自己的搜索 / 排序会重置（图表不重置）；
- 模型视图若同时存在服务端的空 `model` 行与合并段，会出现两个「其它」（数值各自正确）；
- `POST /refresh` 仍返回全量段（这次只优化了 `GET /snapshot` 的下发）；
- 性能三项未动（上一轮列的 B1 / B4 / B5）：宿主重启后首次全量折叠 15.3 s、随包聚合价目 2.67 MB、`snapshot.json` 是美化写盘（约 170 KB 是缩进）；
- 英文版待办照旧：19 条价目说明的 `noteEn`、`snapshot.issues[].message` 双语；
- 词典型 `quota.*` / `q.*` 里还有 6 个服务端 code 间接映射的 `issue.*` 键无法静态判定引用，保留观察。

- **错峰计价（两处真 bug）**：① `offPeakTokenShare` 缺星期参数 → 「周末全天」窗口把工作日也按半价算（单日成本减半）；② 多天范围无小时分布 → 全按高峰价（本月成本高 30%+）。修法：`hoursByDateOf` 按天聚合 24 槽 + `annotateCosts` 逐日按当天星期与占比加权，使用明细 / 热力图 / 总览三处同口径。
- **启动埋点**：`apply()` 记「插件已挂载」（`process.uptime`）、首屏请求记「首次快照请求」；客户端记「客户端插件已挂载」「首屏已渲染」。实测宿主启动 → 插件挂载 2.5 s（本插件模块加载 25 ms），Electron 主进程 → host 进程约 3 s。
- **MCP 全部从 preset 移除**（用户机器侧操作，不入库）：`cordis.patch.yml` 删掉 13 个 MCP 客户端行（每个子进程启动实测 7.5–23 s），备份与恢复片段在 `.trash`。
