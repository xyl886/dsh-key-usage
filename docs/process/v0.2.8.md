# v0.2.8（2026-11-09 发布）—— 成本口径统一 · 概览跟随筛选

## 这一版做了什么

- **服务端统一成本索引**：新增 `src/server/data/costing.ts`，按「天 × 模型」一格计价，错峰按**当天星期几 + 该模型自己的小时曲线**加权。使用明细 / 会话 / 项目 / 模型 / 会话详情 / 按时段六处全部改读这一份，同一批 token 不再出现「明细按逐日错峰、分布页按高峰价」两套基准。
- **概览 KPI 与使用明细同源**：去掉「近 30 天且无筛选时读 summary 官方月列」的分支，KPI 一律由当前窗口 + 当前筛选的 `/usage` 合计计算。
- **金额精度**：内部统一保留 6 位小数、只在渲染层收两位；移除逐行 / 逐时 / 逐通道的四舍五入到分，小额模型行不会再被抹成「0.00 / 无依据」。
- **顶部筛选打通参数化端点**：`/usage` 支持 `project`；`/projects`、`/models` 支持 `provider` / `model` / `project` 并按筛选重算行内 calls / tokens / 成本；新增 `GET /hourly`（7×24 调用数与多指标矩阵，窗口 + 三筛）。
- **概览跟随筛选**：项目排行、模型排行、按时段全部跟随范围 + 通道 / 项目 / 模型；「全部」范围下趋势与热力图悬停的模型构成也不再是固定长期画像。
- **未计价用量透出**：合计与行带 `unpricedTokens`，有未计价 token 时标「部分未计价」；筛选后用量为 0 的项目行不再占位。
- **模型名版本尾巴归一**：`-20260101` / `@2026-01` / `-latest` 视为同一模型；本机价目副本读回时保留 `litellm_provider`，刷新后别名匹配不退化。

## 关键取舍

- **成本在构建期算一次，不在展示时各算各的**：统一索引的代价是本地重建多一次成本聚合，换来的是六个页面口径唯一；`/usage` 按范围现算时也走同一批构建器，不新增第二套公式。
- **错峰按「天 × 模型」加权，不按整段窗口摊**：拿不到小时分布时按高峰价算（宁可偏高，不猜折扣）；「按时段 / 分时」的每格金额仍用该小时自己的模型桶，不用按天数据摊分。
- **项目筛选下接受不完整**：台账没有 workspace 维度，项目筛选只剩会话事件，合计显式标 `officialIncomplete` / `estimated`，不把会话估算冒充官方账单。
- **金额内部 6 位小数**：小用量模型（夹具里 0.00057 USD）不再被舍入成 0 而误判「免费 / 无依据」，显示层再收两位。
- **成本角标保留、不合并口径**：KPI 成本卡仍标「官方账单 / 估算 / 订阅制估算 / 部分未计价」，把数据来源判断交给用户，而不是把不同口径的数字混成一个。

## 遗留

- 台账停更后近 30 天全部为估算，页面必须明确标「估算」；金额角标多、解释性文字偏重（0.2.9 改为页面只留数值，未计价用 `*`、口径说明收进设置页）。
- 项目筛选口径边界：台账没有 workspace 维度，只能统计会话事件，项目筛选下的总成本可能小于全量台账口径。
- 按时段从「长期画像」改为跟随顶部筛选；不筛选且窗口覆盖全年时与旧口径等价，但窄窗口下与旧页面的数字不再直接可比。
- `costing.ts` 与 `routes.ts` 里仍有若干重复取数路径，留给后续重构。
