## 其他安装方式

```bash
dsh plugin --profile web add github:xyl886/dsh-key-usage   # 从 GitHub 装（包内含构建产物）
dsh plugin --profile web add link:/path/to/dsh-key-usage   # 本地开发：软链到仓库，改文件即时生效
dsh plugin --profile web remove dsh-key-usage              # 卸载（桌面端在 Plugin Hub 里操作）
```

- 桌面端 CLI 被应用独占，只能改 profile 依赖：`& $node $pnpm --dir "$env:USERPROFILE\.dsh\profiles\desktop" add dsh-key-usage`（`$node` / `$pnpm` 用 DSH 自带运行时路径，见 [`AGENTS.md`](../AGENTS.md)）。
- **`desktop` profile 的插件来源有两种模式，动手前先确认当前是哪种**（`node_modules/dsh-key-usage` 是 Junction = `link:` 模式，是真目录 = registry 版）：
  - **`link:D:/EasyJob/.plugin/dsh-key-usage`**：本地开发 / 验收用，改本仓库即时可见、不用重装；服务端改动要退出重开 DSH；
  - **`dsh-key-usage@<版本>`**：跑 npm 上发布的那一份，**改本仓库不影响界面**。
  两种模式互切都先 `pnpm remove dsh-key-usage` 再 `add` 目标（先 remove 再 add registry 版，否则会踩下面的 `ERR_PNPM_EPERM`）。
- 从 `link:` 切到 registry 版若仍报 `ERR_PNPM_EPERM`，把 `node_modules/dsh-key-usage`（junction）**改名让开**再装 —— pnpm 会试图导入旧链接内部的 peer 依赖。装完确认 `~/.dsh/profiles/desktop/package.json` 里 `dependencies.dsh-key-usage` 与 `dsh.profile.bundles` **两处都在**（pnpm 不维护 `bundles`）。

## 产物契约（改这几处会踩坑）

- **客户端入口固定** `src/client/index.tsx` → 产物 `client/client.js`，必须是单文件 CJS + `window.__ModuleLoader__.load({ id, factory })` 头（`scripts/normalize-client-banner.mjs` 会校验并归一化 banner）。不要改 entry、产物名或加载方式；
- **`lib/` 与 `client/` 都要提交**：插件以包形态安装时宿主直接读这两个目录，CI 有一道闸会重新构建后要求 `git diff --exit-code`；
- **`data/pricing-catalog.yml` 与 `data/` 必须随包发布**（`package.json` 的 `files` 已声明，与 `lib/` / `client/` 平级，不打进 bundle）：两者都用 `new URL('../…', import.meta.url)` 从包根定位。缺了不会抛错，但对应的价目层整体失效（内置价目缺失 → **通道内价目**只剩聚合价的通道别名命中，跨通道的同模型官方价目照常可用；聚合价缺失 → `aggregate.loaded = "none"`，通道内价目只剩内置那一档、同模型官方价目整层没了，成本多半直接显示 `—`）。改价 = 改 `data/pricing-catalog.yml`；改快照后要同步 `data/README.md` 的「字节数 / sha256 / upstream commit / 抓取日期」四行；
- **快照按二进制存**：`.gitattributes` 里 `data/litellm-model-prices.json -text` 不做任何换行转换，否则 Windows 的 `core.autocrlf` 会改字节、sha256 对不上；
- 客户端构建必须**与机器无关**：`tsdown.config.ts` 用仓库相对路径做虚拟模块 id、按字典序输出 CSS 导出表，否则不同机器构建出的 `client.js` 不一致，CI 的产物同步闸会失败；
- `tsc --noEmit` **不会**更新 `lib/`，而测试 import 的是 `lib/*.js` —— 改了服务端要先编译再跑测试；
- `cordis.yml` 是应用重写的组合产物，插件集变化期间会短暂变成空模板，因此通道提取会回退到 `cordis.patch.yml`。

## CI 与发布

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 push / PR 上跑 `pnpm run verify`，另加两道闸：**构建产物必须与源码同步**（重新构建后 `git diff --exit-code`）与**发布包必须含三件套**（`lib/index.js`、`client/client.js`、`cordis.patch.yml`）。第二道闸**不检查** `data/pricing-catalog.yml` 与 `data/`，而两者都是运行必需项 —— 发布前用 `npm run pack:dry` 的清单确认它们在包里。

发布是**人工触发**的独立工作流 [`.github/workflows/publish.yml`](../.github/workflows/publish.yml)：默认 `dry_run=true` 只校验打包，改成 `false` 才真正 `pnpm publish --provenance`。本机发布：`npm version patch --no-git-tag-version` → `npm publish`，发布前跑完 `verify` / `pack:dry`。

**npm token 管理**：一个 token 只干一件事 —— 发布用 Granular token 只勾 `dsh-key-usage` 包、`Read and write`、勾 Bypass 2FA、90 天有效期；撤回 / 删版本另建一个**不勾 Bypass 2FA** 的 token 临时用（`npm unpublish` 需要它 + `--otp=`）。值只放本机 `~/.npmrc`（600）或 CI Secret `NPM_TOKEN`，绝不写进仓库；怀疑泄露时**先 Revoke 再改密码**。`npm unpublish` 是破坏性操作，官网「Delete package」删的是整包并锁 24 小时，单版本撤回只有 CLI 支持。

## 离线自检

自检全部落在**仓库内的测试与夹具**上：不读宿主实现、不联网、不改文件 —— 唯一例外是 `check:tokens`（读宿主归档核对令牌）。

```bash
npm run check            # lib/**/*.js 语法检查（自动枚举，不再手写清单）
npm run test             # 全部离线测试（自动枚举 test/*.test.mjs）
npm run check:tokens     # 宿主设计令牌自检（唯一要读宿主归档的一项）
npm run check:ui         # UI 刻度 + 状态类配对
npm run check:css        # 组件引用的 CSS Module 类名必须存在
npm run check:eol        # src / scripts / test 必须是 LF
npm run check:i18n       # 中英词典键必须一致
```

- 测试覆盖：台账 / 通道 / 会话折叠（含工具与词频索引）/ 工具窗口 / 会话元信息 / 归档 / 合并 / 实时额度 / 价目（含内置价目回归基线）/ 客户端价目与币种 / YAML 子集 / 聚合价目 / 汇率 / 存储迁移 / 快照 / 日志落库 / 客户端日志 / 端点契约 / 导出 CSV / 更新检查；
- `test/fixtures/pricing-catalog.golden.json` 是**内置价目的回归基线**：`data/pricing-catalog.yml` 逐条解析结果必须与它深度相等，同时断言该文件确实随包发布（`test/pricing.test.mjs`）；改价目时同步更新，否则测试会挡住；
- `test/model-prices.test.mjs` 直接读**真实的随包快照**，因此它同时是「快照没被换行转换弄坏」的哨兵：sha256 要与文件本体、`data/README.md`、测试里的硬编码锚点三处一致。

**宿主设计令牌自检**（`npm run check:tokens` → `scripts/check-design-tokens.mjs`）是这组自检里唯一的例外：它要读**宿主归档**，不读仓库内的夹具。

- 做法：把插件里出现的每个 `--dsw-*` 收集起来（扫描范围见下一条），逐个在宿主归档里核对是否**真实声明过**（宿主共 120 个 `--dsw-alias-*`）；只被 `var()` 引用、从未声明的令牌在真机上会取到空值，肉眼很难发现；
- **找不到宿主归档时只提示并退出 0**（默认路径是 Windows 桌面端的 `D:\soft\DeepSeek Harness\resources\app.asar`，可用 `--asar <path>` 指定），所以 CI 与别人的机器上不会因此失败；也正因为它可能被跳过，它进 `verify` 但不能替代本地跑一次；
- 扫描范围：`src/client/styles/*.css` **与** `src/client/**/*.ts(x)`（组件内联 `style={{ … }}`、`channels.ts` 里的颜色数组都算）。
