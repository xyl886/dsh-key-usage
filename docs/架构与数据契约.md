## 2. 客户端契约

### 2.1 产物形态（不能改）

- 入口：`src/client/index.tsx`（`tsdown.config.ts` 的 `entry`）。
- 产物：`client/client.js`，单文件 CJS，`platform: browser`，`target: es2022`。
- 外层头必须是单行：

  ```js
  window.__ModuleLoader__.load({ id: "dsh-key-usage", factory: (require) => {
  ```

  由 `scripts/normalize-client-banner.mjs` 在构建后强制校验；头不匹配会 `exit 1`。
- `react` / `react/jsx-runtime` 是 external，由宿主 `require` 注入；其余 import 全部打进 bundle。

### 2.2 CSS Modules 内联机制

`tsdown.config.ts` 里的 `dsh-css-modules-inline` 插件把每个 `*.module.css` 变成虚拟模块：

- 用 lightningcss 编译，`cssModules.pattern = '[hash]_[local]'`（类名会加哈希前缀）。
- 注入一个 `<style data-plugin="dsh-key-usage" data-plugin-css="dsh-key-usage/<文件basename>">`。
- 去重键是 **`插件id/文件basename`**：

  ```js
  if (document.querySelector('style[data-plugin-css="dsh-key-usage/section.module.css"]') === null) { …append… }
  ```

  ⇒ **不同目录下的同名 CSS 文件，后一个会静默不注入**。拆样式时 basename 必须唯一。
- 另有一份 `globalThis.__DSH_PLUGIN_CSS__` 注册表（`{tagId, css}[]`）供宿主侧复用。

### 2.3 样式令牌

统一使用宿主 `--dsw-alias-*`，每种都带兜底色（暗色主题）。参考 `package.json` 里其他插件的用法：

| 用途 | 令牌 |
| --- | --- |
| 主/次/三级文字 | `--dsw-alias-label-primary` / `-secondary` / `-tertiary` |
| 卡片背景 | `--dsw-alias-bg-layer-2`（tooltip 用 `-bg-layer-3`） |
| 边框 | `--dsw-alias-border-l1` / `-l2` |
| 强调色 | `--dsw-alias-state-business-primary`（**`state-accent-primary` 宿主里不存在**） |
| 成功 / 警告 / 错误 | `--dsw-alias-state-success-primary` / `--dsw-alias-state-warn-primary` / `--dsw-alias-state-error-primary` |

## 3. 服务端契约

### 3.1 通用规则

- 共 17 个端点：14 个只读 `GET` + 3 个写 `POST`（`/dsh-key-usage/refresh` 手动刷新快照、`/dsh-key-usage/pricing/refresh` 刷新价目、`/dsh-key-usage/log` 追加 / 清空系统日志）；`Cache-Control: no-cache`；`Content-Type: application/json; charset=utf-8`。
- `requireLoopback(request, response)`：`socket.remoteAddress` 不是 `127.0.0.1` / `::1` / `::ffff:127.0.0.1` 时返回 `403 {"error":"loopback only"}`。
- 家目录解析：`process.env.DSH_HOME ?? ~/.dsh`（`routes.ts: dshHomePath()`）。
- 文件缺失 / JSON 损坏 → 返回**空态而不是错误**：

  | 情况 | 响应 |
  | --- | --- |
  | 台账缺失或损坏 | `/usage` → `{totals:null, days:[], availableFrom:null, availableTo:null}`；`/heatmap` → `{days:[]}` |
  | 快照缺失或损坏 | `/quota` → `{providers:[]}` |
  | cordis.yml 缺失 | `/channels` → `{channels:[]}` |

### 3.2 `GET /dsh-key-usage/channels`

```jsonc
{
  "channels": [{
    "provider": "opencode-go",          // cordis.yml providers 下的键（provider id）
    "displayName": "opencode-go",
    "apiKeyEnv": "OPENCODE_GO_API_KEY", // 环境变量名，无则 null（绝不读值）
    "baseURL": "https://…",
    "models": [{ "id": "glm-5.3-flash", "name": "GLM-5.3 Flash", "contextWindow": 1000000 }],
    "costMode": "sub",                  // sub | perToken | free | none | unknown
    "costLabel": "订阅制",               // 服务端给出的中文标签
    "status": "warn",                   // ok | warn | danger | off
    "quotaPercent": 76,                 // 订阅窗口最高占用，无则 null
    "quotaWindowKey": "month",
    "quotaWindowLabel": "本月",
    "balanceText": null,                // 余额展示文本（含币种，原样），无则 null
    "snapshotUpdatedAt": 1790762819897  // 快照写入时间，无则 null
  }]
}
```

顺序：`llm-deepseek` 条目（若有）被 `unshift` 到最前，其后是 `llm-pi-ai.config.providers` 的声明顺序。

**判定规则**（`collect.ts: classifyChannels`，客户端只负责展示）：

| 顺序 | 条件 | costMode | status |
| --- | --- | --- | --- |
| 1 | `apiKeyEnv` 为空 | `unknown` | `off`（未配置） |
| 2 | provider 为 `local` 或 baseURL 指向 127.0.0.1 / localhost / 0.0.0.0 | `none` | `ok` |
| 3 | 快照有 `plan.windows` | `sub` | 最高占用 ≥90 `danger`、≥60 `warn`，其余 `ok` |
| 4 | 快照有 `balance` | `perToken` | 余额 ≤0 `danger`、<10 `warn`，其余 `ok` |
| 5 | `FALLBACK_COST_MODES` 显式登记（当前只有 `sensenova → free`） | 该值 | `ok` |
| 6 | 以上都不命中 | `unknown` | `ok` |

提取规则（`collect.ts`）：

- `llm-pi-ai` 段：`^ {4}providers:$` 起，到下一个 0 列 `- id:` 止；provider 块为 6 空格键名，模型为 10 空格 `- id:`。
- `llm-deepseek` 独立条目：模型在其 `config.models` 下（6 空格 `- id:`），`provider` 固定为 `deepseek-official`，`displayName` 固定 `DeepSeek`。
- **不能换成通用 YAML 解析器**：文件里有 `!!js` 表达式，解析即执行。改规则必须配样本测试。
- YAML 标量的成对引号会被剥掉（`'GLM-5.3-Flash '` → `GLM-5.3-Flash `，尾随空格保留）。

### 3.3 `GET /dsh-key-usage/usage`

| 参数 | 说明 |
| --- | --- |
| `from` / `to` | `YYYY-MM-DD`，缺省取台账首/末日；闭区间 |
| `provider` | 逗号分隔的 **provider id** 列表；缺省不过滤 |

```jsonc
{
  "totals": { "date": "", "calls": 11189, "inputTokens": …, "outputTokens": …, "cacheReadTokens": …,
              "cacheWriteTokens": …, "reasoningTokens": …, "cost": 7.1 },
  "days": [{
    "date": "2026-09-30", "provider": "",           // 注意：日级行的 provider 固定为空串
    "calls": 370, "inputTokens": …, "outputTokens": …, "cacheReadTokens": …, "cost": 0,
    "models": [{ "provider": "opencode-go", "model": "GLM-5.3-Flash ", "date": "2026-09-30", "…": "同 LedgerModelEntry" }]
  }],
  "availableFrom": "2026-09-07", "availableTo": "2026-09-30"
}
```

- `days` 只包含**当天有数据**的日期（无记录的日期被跳过，不会补 0 行）。
- `days[].models` 按 `input+output+cacheRead` 降序。
- `totals.date` 固定为 `''`。
- `hours`：**仅当 `from === to`** 时返回 24 个小时槽 `{ calls, buckets: { inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens } }`，其余情况为 `null`。这份数据来自**会话事件**（不是台账），所以与同一天的 `days[0]` 不保证逐位相等 —— 界面在按小时视图下标注了来源，且不显示成本。

### 3.4 `GET /dsh-key-usage/heatmap`

范围 = `max(台账首日, 今天-364 天)` ~ 台账末日（**服务端不返回未来日期**，未来格由客户端补齐）。

```jsonc
{ "days": [{ "date": "2026-09-30", "totalTokens": 137900000,
             "models": [{ "provider": "opencode-go", "model": "GLM-5.3-Flash ", "totalTokens": 120000000 }] }] }
```

- 只包含 `totalTokens > 0` 的日期；`models` 按 `totalTokens` 降序，同 provider 同名模型已合并。
- 客户端拿不到「台账起始日」本身，只能用 `days[0].date` 近似 —— 这是当前热力图「台账尚未覆盖」判定的依据（见 02 文档 O6）。

### 3.5 `GET /dsh-key-usage/quota`

```jsonc
{ "providers": [{
    "provider": "opencode-go",
    "displayName": "opencode-go", "credential": "OPENCODE_GO_API_KEY",  // 变量名，不是密钥
    "source": "live",              // live = 刚查到的官方数据；snapshot = 回落本机快照
    "fetchedAt": 1760…,            // 实时查询时间（source=live 时有效）
    "updatedAt": 1759…,            // 快照时间 / 或等于 fetchedAt
    "error": null,                 // no-key / network / timeout / unauthorized / http-<code> / bad-json / no-snapshot
    "balance": { "currency": "CNY", "totalBalance": "1.50" },         // 官方返回的归一化字段
    "plan": { "windows": [{ "key": "5h|week|month|day", "percent": 19, "resetsAt": "2026-10-13T15:00:00.000Z" }] }
}]}
```

- 每个**已配置通道**一条；`balance` / `plan` 可为 `null`。
- 实时查询见 `live-quota.ts`：`opencode-go` → `GET https://opencode.ai/zen/go/v1/usage`（`rolling`/`weekly`/`monthly` → `5h`/`week`/`month`）；`deepseek-official` → `GET {baseURL}/user/balance`；另有 openrouter / moonshotai / zai 的官方余额接口。
- **币种来源**：接口自带 `currency` 优先 → 否则按 host 推断（`*.moonshot.cn` → CNY、`api.z.ai` → USD、`open.bigmodel.cn` → CNY）→ 都没有才用方案默认值。z.ai 的余额端点**没有官方文档**，币种只有「定价页注明 USD」这一点有依据。
- **时间字段**：`resetsAt` 同时接受 ISO 字符串与 epoch（毫秒/秒/数字字符串）并统一归一为 ISO，识别不出时原样返回，避免界面显示「重置于 1791903600000」。
- **响应上限**：`MAX_RESPONSE_BYTES = 65536` **按 UTF-8 字节**计算（不是 `string.length` 的 UTF-16 码元数）。
- **回落顺序**：实时 → **统一快照的配额段**（`snapshot.json`，见 §3.18）→ 宿主的 `provider-snapshots.json`（可能很旧，只在首次构建时当种子）→ 无。响应带 `capturedAt` / `stale` / `error`，界面据此显示「数据时间 X · 本机快照 · 实时查询未成功 · 查看系统日志」（`error` 原文只进系统日志，见 §3.19）。
- **`supported`**：该通道是否存在官方余额/窗口方案（`schemeIdOf(channel.provider) !== null`）。`false` 表示**根本没有接口可查**（免费额度、本地端点），界面只显示口径说明、不再提示「实时查询未成功」。
- **错误分档**：`no-key` / `network` / `timeout` / `unauthorized`（401 与 403 合并，OpenRouter 的 403 表示「需要 Management Key」）/ `http-<code>` / `bad-json` / `too-large` / `no-snapshot`；厂商契约 fixture 见 [`test/fixtures/providers/`](../test/fixtures/providers/)（36 个，逐条标注官方/社区/推断来源）。
- **写盘**：只写 `$DSH_HOME/dsh-key-usage/` 下的 `snapshot.json`（见 §3.18）、`model-prices.json`（见 §3.15，校验不过不覆盖）、`fx-rate.json`（见 §3.16）与 `plugin.log`（见 §3.19），不碰宿主的任何文件；同目录的 `quota-snapshots.json` 已不再写入（仅首次构建时读一次当种子）。
- 6 秒超时、64 KiB 上限、60 秒缓存（`?fresh=1` 强制重查）；任何失败回落快照并把原因放进 `error`。
- 宿主的 `provider-snapshots.json` 由「dsh-usage」能力写入，本插件只读；本机实测它最后写入停在 **2026-09-30**，这正是需要自带快照的原因（见 `quota-snapshots.ts` 顶部注释）。

### 3.6 `GET /dsh-key-usage/summary`

总览表用的「今日 / 近 30 天」按通道汇总，全部来自**台账**。

```jsonc
{
  "channels": [{ "provider": "opencode-go",
                 "today": { "provider": "opencode-go", "calls": 0, "tokens": 0, "cost": 0 },
                 "month": { "provider": "opencode-go", "calls": 10588, "tokens": 4090000000, "cost": 0 } }],
  "range": { "today": "2026-10-13", "monthFrom": "2026-09-14" }

```

- 「今日」按**服务器当天**计算；「近 30 天」= 今天往前 29 天到今天。

### 3.7 `GET /dsh-key-usage/sessions?limit=200`

```jsonc
{
  "rows": [{
    "id": "session-43c91b48-…", "title": "开发 DSH Key 用量插件" ,
    "archived": false,      // 宿主侧是否已归档（只做标记，用量照常计入）
    "workspace": "D:\\EasyJob", "provider": "opencode-go", "providerLabel": "opencode-go",
    "firstTime": 1791…, "lastTime": 1791…, "calls": 128, "tokens": 42000000,
    "cacheHitRate": 96.2, "days": 3, "crossDays": 2,
    "prompt": "把会话用量这页加上详情抽屉…",   // 首条真实提问片段（≤200 字，搜索与兜底标题都用它）
    "models": [{
      "provider": "opencode-go", "model": "GLM-5.3-Flash", "tokens": …, "calls": …, "buckets": {…},
      "sharePercent": 82.4,   // 占该会话展示口径 tokens 的百分比（一位小数）
      "cost": 12.3, "costSource": "catalog"   // 逐模型成本与来源（与整行同一套口径）
    }],
    "costMode": "sub",      // 该通道的计费模式
    "cost": null,           // 按两层价目算出的金额；两层都没命中时为 null（界面显示 —）
    "modelCount": 7,        // 该会话出现过的模型个数（models 只给前 5 个，计数看这个）
    "parentSessionId": null,        // 子代理会话指向的父会话 id；普通会话为 null（seed 续接的会话也算普通会话）
    "origin": "subagent",           // 子代理会话为 "subagent"，其余为 null
    "subagentCount": 2,             // 挂在这个会话下的子代理会话数
    "subagentTokens": 1200000       // 这些子会话的 tokens 小计（只标注，不并入本行）
  }],
  "coverage": { "status": "complete", "totalSessions": 12, "countedSessions": 12, "skippedSessions": 0 },
  "priced": true
}
```

- `rows` 按 `lastTime` 倒序；`limit` 只管**返回条数**（上限 1000），与会话折叠数量无关 —— 折叠本身不设上限（§3.9）。
- `title` 来源优先级：**会话投影**（`storages/session_projcache/sessions/<sessionId>.json` 的 `record.rows.title.val` = 侧边栏显示名）→ 旧的聚合投影文件 `session_projcache.json` → 会话 header 的 `title|name|summary|label` → 折叠出的**首条真实用户提问**（跳系统注入文本、截 60 字）；都没有则 `null`，界面回落成 `（无提问）· <短 id>`。
  ⚠️ 只读旧聚合文件是不行的：宿主已把投影拆成「一会话一文件」（本机 167 个文件 / 55 MB，实测全量解析 331 ms，之后按 mtime 缓存每次只 stat ≈ 16 ms），旧文件只剩少量历史条目，绝大多数会话会退化成提问片段 —— 那正是「会话名字和侧边栏对不上」的根因。
- `prompt` 是同一段提问的**片段**（≤200 字）：标题之外给搜索用；正文全文只在 `/session` 详情里给。
- `crossDays` = 首次与最近的**本地日历日**之差（同一天或时间缺失为 0）；只用于导出（界面上「时长」已经表达了同一件事，不再单独标「跨 N 天」）。
- `models` 只给**前 5 个**（已按 tokens 降序）＋ 一行 `{ provider: "", model: "其它" }` 汇总长尾，避免长尾模型把响应撑大；**整行 `cost` 仍按全量模型算**，合并只影响展示。
- `archived` 来自宿主归档集合（`workspaceRegistry.archivedSessionIds`，取不到时读 `storages/workspace.json`）；**归档只标注不剔除**，统计口径不受影响。
- `workspace` 取 header 的 `cwd|workspace|workspacePath|projectPath|project`；缺失时 `null`，界面归到「未归属工作区」。
- `provider` 由模型归属键（如 `pi-ai/opencode-go/GLM-5.3-Flash`）归一得到，见 §3.9。
- `priced` = 当前**有没有任何价目可用**（内置价目有条目，或聚合价装载成功），不是「本行有金额」；界面据此决定要不要提示「无成本依据」。三个会话类端点（`/sessions`、`/projects`、`/models`）与 `/session` 都用这一个口径。
- **子代理判定以投影为准**：`record.rows.subagent.val.identity` 存在才是子代理；`subagent.val` 是空对象说明这是被 seed 续接的会话（宿主也给它写了父会话链接），**侧边栏当独立会话**，插件也必须当独立会话（`origin` 清空、`parentSessionId` 清空）。投影读不到时才退回 header 的 `parentSession` / `origin` 猜测。
- **子代理会话**（宿主 `@deepseek-ai/dsh-subagent` 起的是独立**子会话**）：`subagentCount` / `subagentTokens` 在 `sessionRowsOf` 里按父 id 聚合。**子会话单独成行、单独计入统计，不并入父会话**（`subagentTokens` 只是父行标注，避免同一份用量被重复计入）；界面默认隐藏子会话与已归档，只在父行标「N 个子会话 · tokens 小计」，主会话详情弹窗里可逐个点开子会话。

### 3.9 会话服务契约（`sessionPersistence`）

`src/server/data/sessions.ts` 只使用下面这组只读接口（0.2 形态），拿不到就降级：

```js
persistence.list()                // → [{ header, revision, eventCount? }]（本机实测不返回 eventCount）
persistence.open(id, "read")      // → handle
handle.read(0)                    // → { events }（offset 含 0；events[i].seq === i）
handle.inheritedEventCount        // fork 继承的事件数
handle.close()                    // 必须调用
persistence.identity              // 服务身份（换实例后缓存失效）
```

- **缓存**：命中 `(id, revision, eventCount)` 即跳过读取；`revision` 变化或服务身份变化时整段重折。
  ⚠️ 本机实测（133 个会话 / 2026-10-13）`list()` **完全没有 `eventCount` 字段**，因此缓存实际只由 `revision` 把关（记录里的 `eventCount` 恒为 `-1`，是无害的占位）。文档与代码都不要声称「eventCount 参与校验」。
- **首次折叠耗时分布**（同一语料实测，133 会话 / 119 MB / 14.4 万事件）：`list()` ≈ 3%、宿主 `open()` ≈ 78~82%（整段 zstd 解压 + JSON.parse，宿主主线程同步）、宿主 `read(0)` ≈ 17~18%（目录路径解析）、**插件自己的折叠 + 汇总仅 ≈ 1%（80~94 ms）**。所以插件侧优化的天花板很低；`sessions.ts` 用**并发 = 2**（>1 MiB 的会话仍串行）把 fs 等待叠起来，实测冷启动中位 6878 ms → 6174 ms（−10.2%，8/8 配对轮均更快）。并发不能调大：宿主冷读 memo 容量为 2（`COLD_LOG_MEMO_MAX_ENTRIES`），3 路并行会把先到的会话挤出 memo 反而整段重解压（实测慢 20%~45%）。回退开关是 `READ_CONCURRENCY = 1`。
- **继承前缀**：只把前缀里的 `request/header` 拿来做模型归属，不计入用量（与参考实现一致）。
- **不设上限**（2026-10-16 移除 `MAX_SESSIONS = 200`）：宿主 `list()` 返回多少就折叠多少，顺序按 header 的 `updatedAt|createdAt` 倒序。以前取最近 200 个，超出部分**静默退出**会话 / 项目 / 模型统计，表现为「数字凭空变小」。
- **降级**：`sessionPersistence` 缺失 → `unavailable`；单会话 `open`/`read`/`close` 失败 → 丢弃该会话并计入 `partial`，绝不污染其它数据。
- 旧形态（`listSnapshots` + `readFrom` + 实时 `sessions.list()`）保留为回退路径，但未做真机验证。

### 3.10 会话事件的折叠口径（`session-usage.ts`）

- 用量样本来源：`assistant/chunk`（`data.chunk.type === "usage"`）、`assistant/message`（`data.usage`），以及 `assistant/message|assistant/attempt` 的 `data.stream[].chunk.usage`。
- 样本键：`turn:step`（缺 turn/step 时用 `seq`）。
- **同一键重复上报 = 覆盖**（不是累加）；`llm/retry-started` 之后同 `turn:step` 的样本属于**新一次尝试**，按新键累加。
- 模型归属：`data.message.source` → 回落最近一次 `request/header` 的 `data.header.config` → 都没有则 `unknown/unknown`。
- 每个样本记 `(day, hour, model, buckets)`，日/小时/模型三个维度的汇总由样本表派生，因此覆盖会同时修正日期与小时归属。
- 「调用次数」= 结算样本数（不是台账里的 `calls`）。
- **首条提问的取文本规则**（只影响「取哪条文本」，不改变标题优先级链）：跳过以 `<system-reminder` / `<system` / `<command-` / `<local-command` 开头的**宿主注入文本**（teammate 系统提示、斜杠命令回显、本地命令输出），取**下一条**人类消息；连续多条系统消息会一直往下找。折叠结果里保留正文全文（截断到 4000 字，详情抽屉用），列表标题截 60 字、搜索片段截 200 字。
- 全是系统消息（没有人类提问）时 `firstPrompt = null`，界面回落成「（无提问）· 短 id」，**不显示空标题**。

### 3.11 会话标题与归档状态的来源（`session-meta.ts`）

| 数据 | 来源（按优先级） | 说明 |
| --- | --- | --- |
| 会话标题 | ① `$DSH_HOME/storages/session_projcache/sessions/<id>.json` → `record.rows.title.val`（按 id 惰性读 + 文件 mtime 缓存）② 旧的聚合投影文件 `session_projcache.json` → `tables.sessions.<id>.rows.title.val` ③ 会话 header 的 `title/name/summary/label` ④ 折叠出的**首条人类提问**（跳过系统注入文本，见 §3.10；压平空白、截 60 字） | ① 就是侧边栏显示名，宿主已把投影拆成「一会话一文件」（本机 167 个文件 / 55 MB，首次全量解析 331 ms、之后每次只 stat ≈ 16 ms）；② 只剩少量历史条目，仅作兜底。④ 的来源改过：以前直接取首条 `user/message`，teammate / 命令类会话会得到 `<system-reminder> You are teammate "…"` 这种没有辨识度的标题 |

> **归档只标注、不剔除**（2026-10-13 的取证结论，原独立文档已并入本节）：
> 归档是逻辑标记 —— 宿主 `archiveSession(id)` 只把 id 追加进 `workspace.json` 的 `global.archivedSessionIds` 并清 pin，**不移动 / 不复制 / 不删除会话文件**；
> `sessionPersistence.list()` 完全不读归档集合，日/时归属又只看事件内 `event.time`，所以**归档当天统计不会缩水**，插件只标注（行标记 + 三档筛选 + 淡化），不参与任何口径。
> 会让历史总量**不可逆下降**的只有物理删除（第三方归档插件的批量删除 / `autoDeleteEnabled`），该功能默认关闭 —— 运维上保持关闭，清理磁盘先用插件管理页的**预览**确认候选数量。
> 与归档无关的「变小」来源现在只剩一个：单会话读取失败（界面标 `coverage = partial`）。会话数上限 `MAX_SESSIONS = 200` 已于 2026-10-16 移除（宿主 `list()` 返回多少就折多少），那条「数字凭空变小」的路径没有了。

### 3.13 价目与成本契约（两层）

**取值顺序（逐格取第一个可用来源）**：`官方账单（台账 cost）` > **通道内价目**（内置官方价目 §3.14 按 `provider + model` 命中 → `catalog`；否则 LiteLLM 聚合价 §3.15 按**通道别名**命中 → `aggregate`）> **同模型官方价目**（本通道没有价目时，聚合价里该模型名**全库唯一**命中 → `model`，多半就是模型厂商自己的官方价；同一厂商常有 `x` 与 `vendor/x` 两条同价键，**同厂商同价也算唯一**；同名候选跨多个厂商时，再用**内置价目里该模型的厂商**当通道查一次 → 仍是 `model`）> `none`（界面显示 `—`）。
`CostSource = 'official' | 'catalog' | 'aggregate' | 'model' | 'none'`；整天 / 整行取**最弱**的那一格（`weakestSource` / `weakestOf`，强弱序 `SOURCE_RANK = { official: 0, catalog: 1, aggregate: 2, model: 3, none: 4 }`）。

实测（`test/pricing.test.mjs` / `test/model-prices.test.mjs`）：`opencode-go` + `moonshot-v1-8k`（别名不命中、聚合价里同名唯一）→ `model` / USD 0.2；`opencode-go` + `deepseek-flash`（同厂商同价双键 `deepseek-flash` 与 `deepseek/deepseek-flash`）→ `model` / USD 0.3；`opencode-go` + `glm-5.3-flash`（10 条跨厂商候选，内置价目知道厂商是 `zai`）→ `model` / USD 0.15；`opencode-go` + `gpt-5.4-mini`（跨厂商、价不同、内置价目也不认识）→ `none`；`deepseek-official` + `deepseek-flash` → `catalog` / CNY。`match-ambiguous` issue 由匹配入口 `matchPricedRule` 在**最终确实定不下来**时记（纯匹配器 `aggregateRuleFor` 不再记），所以「拿到厂商兜底价」的模型不会同时报「已跳过」。

- **不引入任何第三方 YAML 库**，也不用于 `cordis.yml`（那里有 `!!js` 表达式，只做文本提取，见 §3.2）；
- issue 形状 `{ "file": "catalog", "line": 12, "message": "…" }`：`line` 是 1 基行号（拿不到时为 `null`），面板列出前 5 条并说明这些条目已被跳过。

### 3.14 内置官方价目（`data/pricing-catalog.yml` ← `pricing-catalog.ts`）

18 条厂商官方价目，随包发布的仓库根 `data/pricing-catalog.yml` 是**唯一事实来源**（`pricing-catalog.ts` 进程内只读一次、不写、不联网）。
文件缺失或某条写法非法时**带行号报 issue 并跳过该条**，绝不猜单价；改价 = 改这个文件（升级会覆盖，用户不要改）。

| 项 | 约定 |
| --- | --- |
| 数据来源 | 各厂商**官方文档**（DeepSeek / Moonshot·Kimi / Z.ai / OpenRouter），逐条带 `source`（精确 URL）与 `fetchedAt` |
| 只写文档明确给出的价 | 文档没写的档位留空（折算为 0，**不用同类模型或输入价顶替**）；有歧义的一律不猜 |
| 币种 | 按文档原样记录（DeepSeek / Kimi 为 CNY，OpenRouter / Z.ai 为 USD），不跨币种合计 |
| 匹配 | 精确 → 忽略大小写 → 去 `vendor/` 前缀（`deepseek/deepseek-v4.1-flash` → `deepseek-v4.1-flash`）→ 该通道通配；**不做模糊 / 近似匹配**，宁可往下走聚合价、或最终显示 `—` |
| 优先级 | 同为「通道内价目」时，内置价目（`"catalog"`）先于聚合价的通道别名命中（`"aggregate"`）—— 插件默认值优先于第三方聚合价；它是**通道内价目的来源之一、不是必需项**（缺了聚合价照样能给同名模型定价） |

### 3.15 LiteLLM 聚合价目（第三方、USD：随包快照 ← `data/litellm-model-prices.json` / `model-prices.ts`）

聚合价是**「通道内价目」的第二来源**，也是**「同模型官方价目」的唯一来源**：数据来自 [BerriAI/litellm](https://github.com/BerriAI/litellm)
的 `model_prices_and_context_window.json`（**MIT**，原文随包在 `data/litellm-LICENSE.txt`）。插件把上游文件**字节原样**放进包里，
运行时不联网、只在内存里建索引；来源 / commit / 抓取日期 / sha256 记在 `data/README.md`。

**三个上游地址（与 `model-prices.ts` 的常量一致）**

| 用途 | 常量 | 地址 |
| --- | --- | --- |
| 来源页（给人看 / 数据浏览） | `AGGREGATE_SOURCE_URL` | <https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json> |
| 刷新首选（raw） | `AGGREGATE_SNAPSHOT_URL` | <https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json> |
| 刷新备用镜像 | `AGGREGATE_MIRROR_URL` | <https://cdn.jsdelivr.net/gh/BerriAI/litellm@main/model_prices_and_context_window.json> |

**两份文件、一层来源**

| 层 | 路径 | 谁写 | 读取方式 | 缺失 / 写坏时 |
| --- | --- | --- | --- | --- |
| 本机刷新副本 | `$DSH_HOME/dsh-key-usage/model-prices.json` | 面板「刷新价目」（`POST /pricing/refresh`） | 每请求 stat（`mtimeMs:ctimeMs:size` 缓存；同一请求内 250 ms 不重复 stat） | 文件不存在 = 还没刷新过（正常）；不是合法 JSON / 没有可定价条目 ⇒ 记 issue 并**降级回随包快照** |
| 随包快照 | 包根 `data/litellm-model-prices.json`（`new URL('../data/litellm-model-prices.json', import.meta.url)` ⇒ 编译后从 `lib/` 的上一级解析） | 插件维护者（重新抓取步骤见 `data/README.md`） | 同上 | 缺失 / 写坏 ⇒ 该层整体失效（`loaded: "none"`），匹配一律不命中（成本只剩内置价目那一档，没有内置价目的通道直接显示 `—`），**绝不抛错** |

- **可定价条目口径**：排除顶层文档条目 `sample_spec`；只收 `mode` 为 `chat` / `completion`、且 `input_cost_per_token` 与 `output_cost_per_token` 都 **> 0** 的条目（图片 / 音频 / embedding / rerank 等没有可比口径，直接跳过）；模型名取键的最后一段并小写。当前随包快照按此口径是 **2697 条条目 / 1546 个模型名**（2026-10-14 复算；`test/model-prices.test.mjs` 用独立实现复算并要求规模达标）；
- **单位与币种**：上游是 USD / token，装载时 `×1e6` 换算成「每百万 tokens」后**原样并列**（`toPrecision(12)` 只抹浮点尾差）；**不做任何汇率换算**，聚合价规则带 `currency: "USD"`，与人民币价目**分别展示、不合计**；
- **缓存两档**：上游同时有 `cache_read_input_token_cost` 与 `cache_creation_input_token_cost` 时按原值收录；**只收录一档**时缺的那档按**未命中价**（`input`）代，并标 `partial: true`（界面在角标后加「· 部分」，tooltip 写「缓存写入价未收录，按未命中价计」）；两档都没有 = 该模型不支持缓存计价（0/0，**不标 partial**）；
- **匹配算法（冻结口径，`model-prices.ts: aggregateRuleFor`）**：模型名取键末段、查询串同样剥掉 `vendor/` 前缀后按小写比较 → 通道别名表命中（`deepseek-official → deepseek`、`moonshotai → moonshot | moonshotai`、`zai`、`openrouter`、`openai`、`anthropic`、`dashscope`、`azure → azure | azure_ai`、`google → gemini | vertex_ai`、`volcengine`）时，取「键里 `/` 段数最少 → 键名字典序」的第一条（`source: "alias"`）→ 别名不命中时**该模型名全库唯一才用**（`source: "unique"`；同一厂商常有 `x` 与 `vendor/x` 两条**同厂商同价**的键，这种多键也算唯一），否则返回 `ambiguous`（多候选）—— **不猜通道**。`ambiguous` **不在这里记 issue**：上层 `matchPricedRule` 还会用**内置价目里该模型的厂商**当通道再查一次（`glm-5.3-flash` → `zai`），只有最终确实定不下来才记 `match-ambiguous`（按 `provider|model` 去重、上限 200 条），否则面板会出现「报了已跳过却又有金额」。落到成本口径上：`alias` 记成 `aggregate`，`unique` 与厂商兜底都记成 `model`（`pricing.ts: matchPricedRule`）；
- **面板展示**（**页头「口径」弹窗**里的「价目来源与文件」段；原「余额与配额」页的折叠块随该 Tab 一并移除）：装载来源（本地刷新文件 / 随包快照 / 未装载）、条目数、模型数、文件时间、上游 commit 短写法、装载问题清单。

**`POST /dsh-key-usage/pricing/refresh`**（三个写端点之一，见 §3.1）

- 仅回环（非回环 403）；**只接受 POST**（其它方法回 `{ok:false,error}`）；**没有请求体**；
- 服务端 `refreshModelPrices()`：先 raw（`AGGREGATE_SNAPSHOT_URL`）、失败再试 jsDelivr 镜像（`AGGREGATE_MIRROR_URL`）；**两次尝试共享 20 秒总预算**（`AGGREGATE_REFRESH_TIMEOUT_MS`），单次响应上限 **12 MiB**（超限立即 abort）；
- **校验后才写**：响应要能 `JSON.parse` 成对象、每个条目的值都是对象、可定价条目数 ≥ 100，否则整次失败且**不覆盖**已有文件；通过后原子写（同目录 `.tmp` + rename）到 `$DSH_HOME/dsh-key-usage/model-prices.json`（写目标按文件名 + 绝对路径双重校验）；
- 返回**一律 HTTP 200**：`{ok:true,url,bytes,entries,sha256,fetchedAt}` 或 `{ok:false,error}`；**客户端超时 30 秒**，必须大于服务端的 20 秒预算（否则会在服务端正要写盘时 abort）。

### 3.16 `GET /dsh-key-usage/fx?refresh=1`

USD → CNY 实时汇率（服务端第三个、也是最后一个显式联网动作）。**12 小时 TTL 内直接吃本机缓存，一次网络都不发**；`?refresh=1` 强制走上游。

```jsonc
{ "ok": true, "base": "USD", "quote": "CNY", "rate": 7.1,
  "fetchedAt": "2026-10-14T…Z",       // 默认兜底时为 null
  "source": "upstream",              // upstream（刚联网取的）| cache（本机缓存）| default（兜底 7.1）
  "stale": false,                    // 是否已超过 TTL（默认兜底恒为 true）
  "upstream": "https://open.er-api.com/v6/latest/USD",   // 用缓存 / 兜底时为 null
  "ttlHours": 12, "note": "…中文说明（含失败原因）…" }
```

- 上游顺序：`https://open.er-api.com/v6/latest/USD` → `https://api.frankfurter.app/latest?from=USD&to=CNY`，都取 `rates.CNY`；单次 6 秒超时、64 KiB 上限、非 200 / 坏 JSON / 缺 `rates.CNY` 一律算失败；
- 成功即原子写 `$DSH_HOME/dsh-key-usage/fx-rate.json`（写目标双重守卫）；上游全失败时回落缓存（`stale: true`），无缓存则 `source: "default"`、`rate = 7.1`；
- **接口恒为 200 + `ok: true`**，失败原因写在 `note` 里；触发时机只有打开页面 / 切换显示币种 / 点「刷新汇率」，没有定时轮询、没有开机拉取。

### 3.17 `GET /dsh-key-usage/session?id=<sessionId>`

单个会话详情（界面里点会话行打开的抽屉）。**只折叠这一个会话**：`sessionPersistence` 缓存里已折叠过就直接返回（零 I/O），
否则 `list()` 定位头部后单独 `open/read/close` 一次 —— 不会像 `/sessions` 那样重折全部会话。
整表折叠正在进行时先等它结束（宿主的解析 memo 只装 2 个会话，抢着 open 会把它挤掉）。

```jsonc
{
  "session": {
    "id": "session-43c91b48-…", "title": "开发 DSH Key 用量插件", "archived": false,
    "workspace": "D:\\EasyJob",
    "provider": "opencode-go", "providerLabel": "opencode-go", "costMode": "sub",
    "firstTime": 1791…, "lastTime": 1791…, "durationMs": 7200000, "crossDays": 1, "days": 2,
    "calls": 128, "tokens": 42000000,
    "buckets": { "inputTokens": …, "outputTokens": …, "cacheReadTokens": …, "cacheWriteTokens": … },
    "cacheHitRate": 96.2,
    "prompt": "首条真实提问全文（≤4000 字，超长截断）",   // 没有人类提问时为 null
    "models": [{ "provider": "opencode-go", "providerLabel": "opencode-go", "model": "GLM-5.3-Flash",
                 "tokens": …, "calls": …, "sharePercent": 82.4, "buckets": {…},
                 "cost": 12.3, "costSource": "catalog", "partial": false }],
    "hours": [{ "calls": 3, "tokens": 41000 }],   // 24 个槽；没有结算样本时为 null
    "cost": 13.54, "costSource": "catalog"
  },
  "coverage": { "status": "complete", "reason": null },
  "priced": true
}
```

| 情况 | 响应 |
| --- | --- |
| 缺 `id` 参数 | `400 {"error":"缺少会话 id：请用 ?id=<sessionId>"}` |
| 不在宿主会话列表里 | `404 {"error":"会话不存在","id":"…","reason":"…"}` |
| 会话存在但读不出来 | `200` + 会话头字段（标题 / 工作区）与空用量，`coverage.status = "partial"`、`reason` 写明失败原因 |
| 宿主没有会话服务 | `200` + `coverage.status = "unavailable"`、`reason` 说明；不抛错、不影响其它端点 |
| 非回环 | `403 {"error":"loopback only"}`（与其它端点一致） |

- `hours` 是**一天里的哪个时段**的分布：跨天会话按小时累加（不是逐日序列），界面画 24 柱迷你图。
- `buckets.cacheWriteTokens` 只参与计费，不计入展示口径 `tokens`（口径见 §4）。
- 详情里的 `models` **不做**「其它」合并（只统计一个会话，长尾有限）；`cost` / `costSource` 与 `/sessions` 同一套取值（最弱的那一格）。

### 3.18 `GET /dsh-key-usage/snapshot` 与 `POST /dsh-key-usage/refresh`（统一快照）

`snapshot.ts` 把 5 个 Tab 的数据物化成一份 `$DSH_HOME/dsh-key-usage/snapshot.json`（**唯一数据来源**）：
各 Tab 端点（`/channels`、`/summary`、`/quota`、`/heatmap`、`/models`、`/projects`、`/sessions`）改为直接读快照或调用同一批构建器函数；
参数化端点（`/usage?from&to&provider`、`/session`）保留现算，但走同一套聚合函数与同一份本地 mtime 缓存。

- **响应**（两个端点同一形状）：

  | 字段 | 说明 |
  | --- | --- |
  | `updatedAt` | 本次构建完成时间（ISO） |
  | `buildSource` | `initial`（还没有快照时现算）/ `scheduled`（5 分钟定时）/ `manual`（手动刷新） |
  | `building` | 此刻是否有一次构建在进行；为真时返回的是**上一份完整内容**，不是半成品。构建进行中**不干等**（`view()` 直接把手上这份给出去）：以前首开要等整轮构建跑完，实测 1～14 s |
  | `quotaRefreshing` | 此刻是否有一次**后台配额补查**在进行（页面打开时触发）；客户端据此在 1.5 s 后追取，最多 6 次 |
  | `sections` | `{ overview, channels, usage, heatmap, models, projects, sessions, quota }`，每段形状与对应端点一致；`usage` 存**默认范围**（近 30 天 / 全部通道） |
  | `quotaOutcome` | `{ refreshedAt, providers: [{ provider, ok, error, capturedAt, stale }] }`：每个通道这次查到没、展示值的时间、失败原因 |
  | `issues` | `[{ kind, message }]`，含 `build-duration`（每次构建耗时都记一条，≥**4000 ms** 时额外注明「超过 4000 ms 阈值」：`SNAPSHOT_SLOW_BUILD_MS = 4000`，2026-10-16 从 2000 提高 —— 实测 54 次采样里 42 次超 2000 ms，日志被这条刷满，而会话读取明细已经每次落盘）、`build-failed`、`channels-failed`、`quota-failed`、`write-failed` |

- **重建周期与联网边界**：本地段每 **5 分钟**重建（`setInterval().unref()`，不联网）；配额段在 `initial` / `manual` / `POST /quota?fresh=1` / **打开页面的后台补查**时联网，`scheduled` 与 `open` 一律不碰厂商接口。`GET /snapshot?fresh=1`（页面打开）时：本地段距上次重建 ≥ **10 秒**（`SNAPSHOT_OPEN_MIN_MS`）就**阻塞**重算一次（只算本地，热缓存下几百毫秒），配额段距上次查询 ≥ **60 秒**（`SNAPSHOT_QUOTA_TTL_MS`）就**后台**补查一次（不阻塞首屏、单飞、失败静默，返回体标 `quotaRefreshing: true`，客户端随后追取）。补查用 `force: false`，由 `live-quota` 自身的 60 秒缓存做第二道闸门 —— 同一分钟内反复打开不会重复打上游。
- **串行化**：同一时刻只允许一个构建；`POST /refresh` 撞上在跑的构建会等它结束（上限 **10 秒**），超时返回 `{ok:false,error:"正在重建数据，请稍后重试"}`（HTTP 200）。
- **写盘**：同目录临时文件 + rename 原子写，写目标按文件名 + 绝对路径双重校验；**构建失败不覆盖上一份好快照**。
- **构建顺序**：配额（仅 `initial` / `manual`）→ 本地段（用同一份配额判定通道成本模式，顺序反了会出现「快照 `costMode=unknown`、端点是 `sub`」的同源不一致）→ 用配额结果重建 `channels` → 写盘；`scheduled` / `open` 跳过配额那一步，沿用现值。
- **一次构建只读一遍会话**：`builders.local` 先 `sessionSource.collect()` 取出同一份 collection，再喂给 `modelsPayload` / `projectsPayload` / `sessionsPayload`（此前三段各自 `collect()`，同一次构建把宿主会话列表与变更会话读三遍，实测 p50 3.3 s、最高 13.8 s）。
- **会话读取明细每次落盘**：本地重建用 `sessionSource.stats()` 把 `{ sessions, cached, read, listMs, readMs, totalMs }` 以 `info` 追加进 `plugin.log`（消息「本地重建：会话读取明细」），**不进 `issues`**（这是排查信息，不是快照问题，不该在界面上弹警告）。

### 3.19 `GET|POST /dsh-key-usage/log`（系统日志，`log-file.ts`）

界面上的失败原因（上游 URL、HTTP 状态、错误类型）统一落盘到 `$DSH_HOME/dsh-key-usage/plugin.log`，刷新页面后仍可查；页面上只留一行「结论 · 查看系统日志」（`components/LogHint.tsx`，点击走 `requestOpenLog()`）。

| 项 | 契约 |
| --- | --- |
| `GET /dsh-key-usage/log?limit=500` | `{ ok: true, records: [{ time, level, source, message, detail? }] }`；`limit` 默认 500、上限 2000（`parseLimit`）；文件不存在返回空数组 |
| `POST /dsh-key-usage/log`（`{ records: [...] }`） | 追加写，`{ ok: true, written: n }`；单批最多 **200** 条，超出部分丢弃 |
| `POST /dsh-key-usage/log`（`{ clear: true }`） | 临时文件 + rename 清空，`{ ok: true }` |
| 请求体非法 / 超 128 KiB | `{ ok: false, error }`（HTTP 200），不抛错 |
| 非回环 | `403 {"error":"loopback only"}` |

- **落盘格式**：一行一条 JSON（JSONL）；`message` 截到 400 字符、`detail` 截到 1200 字符，`source` 截到 32 字符，非法 `level` 回落 `info`、缺 `source` 回落 `ui`、非法时间用当前时间。
- **轮转**：追加后超过 **512 KiB** 就只保留后半段（临时文件 + rename），最新一条必须留住。
- **写目标守卫**：文件名 + 绝对路径双重校验，只允许 `$DSH_HOME/dsh-key-usage/plugin.log`。
- **客户端行为**（`src/client/core/log.ts`）：内存里按「来源 + 消息 + 级别」去重累加 `×N`；新建 / 累加过的条目攒 **1 秒**批量 POST（失败静默丢弃，不影响主流程）；**同一条目只落盘一次**（重复出现只在内存累加 `×N`，不再反复写同一行记录 —— 2026-10-16 修，之前同一个已知问题会把 `plugin.log` 刷满）；页面打开时 `GET` 回读最近 500 条并与内存合并（按「时间 + 内容 + 第几次出现」去重，日志窗「刷新」重复读不会虚增计数）；清空同时清内存与文件。
- **记录来源**：`i18n`（缺词）、`api`（端点请求失败）、`snapshot`（快照 issue、「读取不完整」与每次本地重建的会话读取明细）、`pricing`（刷新价目）、`fx`（汇率回落默认值）、`quota`（余额 / 窗口查询失败，含未配置 Key）、`ledger`（会话详情读取失败）、`export`（导出 / 复制被浏览器拦截）、`ui`。
- **绝不允许进日志的内容**：API Key、`Authorization`、cookie、请求头原文（与 §「不碰凭据文件」同一条约束）。

## 4. 统计口径（改动前必须确认）

| 指标 | 口径 | 位置 |
| --- | --- | --- |
| **Tokens（展示口径）** | `inputTokens + outputTokens + cacheReadTokens`，**不含** `cacheWriteTokens` 与 `reasoningTokens` | 客户端各处、`buildHeatmap`、`summarizeSession` |
| 命中率 | `cacheReadTokens / (inputTokens + outputTokens + cacheReadTokens)`，一位小数；**台账表与会话表同一公式**（截图里 3.82B / 3.96B = 96.2% 即此口径） | 客户端与 `cacheHitRateOf` |
| 调用次数 | 台账用 `calls` 原样；会话侧用**结算样本数**；展示时千分位用**空格**（`11 189`） | `fmtCalls` |
| 成本（台账） | `cost` 原样，`¥` + 两位小数；按计费模式区分「订阅内 / ¥0.00 / 无计费 / —」；角标 `官方` | `costCellText` |
| **成本优先级** | 台账当天的**官方成本**（`costSource: "official"`，不重算）> **内置官方价目**（`"catalog"`）> **LiteLLM 聚合价按通道别名**（`"aggregate"`，USD）> **同模型官方价目**（`"model"`：聚合价里同名唯一，含同厂商同价双键与「按内置价目的厂商兜底查到」）> 无（`"none"`，界面显示 `—`） | `routes.ts: annotateCosts` / `pricing.ts: rowCostsOf` / `pricing.ts: matchPricedRule` |
| 成本（会话 / 项目 / 按模型） | 通道内价目优先，其次同模型官方价目，两层都没命中就返回 null → `—`：`Σ(输入×未命中价 + 缓存读×命中价 + 缓存写×写入价 + 输出×输出价) × 单位系数`；**不再回落台账反推均价**（`ledger.ts: estimateCost` 已删） | `pricing.ts: priceRowsByRules` / `pricing.ts: rowCostsOf` |

## 5. 宿主接线

- 插件包内 `cordis.patch.yml`：`insert: [{ id: dsh-key-usage, name: dsh-key-usage }]`；profile 的 `cordis.yml` 末尾有同名条目。
- 客户端 `package.json` 的 `dsh.client.inject` 只有 locale 与 ui-slots 两个宿主包；服务端只声明 optional peer `@deepseek-ai/cordis`，不打包任何依赖。
- **客户端 slot**：`sidebar.panellist`（导航项）与 `main`（整页）配对。历史方案（`settings.section`、`sidebar.footer.action`、插件页配置卡片）已弃用，理由见 [`process/v0.1.0-0.1.5.md`](./process/v0.1.0-0.1.5.md)。
- 开发可用 **`link:` 协议**把仓库挂到 profile：`~/.dsh/profiles/<profile>/node_modules/dsh-key-usage` 变成指向仓库的 Junction，改动即时可见、不需要重装。

**改动生效条件**（实测 2026-10-13）：`client/client.js` 重新构建 + 刷新页面；`lib/*.js` 必须**退出重开 DSH** —— 插件在挂载时进入 Node 的 ESM 模块缓存，Hub `/restart` 在桌面端不可用，无热重载途径。

**通道配置来源（易踩）**：`cordis.yml` 是应用按需重写的组合产物，插件集变化期间会短暂变成空模板（实测 47,753 B → 223 B → 47,753 B），所以 `loadChannels()` 取不到就回退 `cordis.patch.yml`（`test/routes.test.mjs` 覆盖）；patch 层的 `local` 通道不写 `apiKeyEnv`，判定顺序是「先本地端点、后未配置」。

## 6. 已知限制

1. 台账维度是「天 × provider × 模型」，**没有小时 / 项目 / 会话维度**；这三者由宿主会话事件折叠得到（§3.9、§3.10）。两套数据源口径不同，同一枚数字在「使用明细」与「会话用量」里不保证相等。
2. `aggregateRange` 对无记录日期不补 0 行，客户端「按天 Tokens（N 天）」的 N 是**有数据的天数**，不是范围天数。
3. 会话事件里的 provider 可能是 pi-ai 路由名（`pi-ai/opencode-go`），`attributeModelKey` 按已知通道名在段边界从右往左归一；匹配不到就原样展示。
4. `sessionPersistence` 的 0.2 契约按参考实现 + 离线夹具写：`list()` 的 header 是否真带 `cwd` / `title`、`open/read/close` 行为是否一致，需要真机确认。
5. 会话折叠**不设数量上限**（宿主 `list()` 返回多少就折多少），成本只按两层价目算、没有依据就显示 `—`（不再按台账均价估算），都是有意的取舍；`coverage` 字段会把不完整状态暴露给界面。
6. `/quota` 快照可能长期不更新（本机为 2026-09-30）；卡片会显示快照时间，但不会自动刷新宿主快照。
7. **中国法定节假日表达不了**：插件没有节假日日历，DeepSeek 的 `note` 已写明「节假日会按高峰价算」—— 偏差方向是成本偏高（保守）。
8. 错峰加权只用得上**单日范围**（`hours` 来自会话事件，且没有「模型 × 小时」拆分）；跨天与多日一律按标准价，属有意保守。小时槽没有日期，带 `days` 的窗口在占比加权里按「每天」近似。
9. **汇率兜底**：上游都取不到且无缓存时用默认 7.1（`source: "default"`），折算值只是量级参考；界面会显式标注「未能联网」。
10. **聚合价这一层的价值主要在「同模型官方价目」**：别名表只覆盖 10 个通道（§3.15），别名基本命不中现有通道；真正出数的是「同名唯一（含同厂商同价双键）」与「按内置价目的厂商兜底」这两条。跨厂商、价不同、内置价目也不认识的模型仍然整条跳过（`none`、显示 `—`），**不猜**。
11. 跨币种合计已修：各汇总在 `cost` 之外并列 `costsByCurrency`，界面**逐币种折算后相加**（§4）；`cost` 只留给导出与老调用方。
